# Modbus 通讯协议说明（旧协议框架改造版）

## 一、总体设计


| 维度         | 取值                                                             | 与旧协议的关系                  |
| ------------ | ---------------------------------------------------------------- | ------------------------------- |
| 帧起始       | **去掉 **`0xC4`** 起始符，帧直接以 **`Unit ID`** 起始**          | 帧边界由 USB-HID 报文边界界定   |
| 长度字段     | **保留 **`Len`**（16 位大端，移到 Func 后并入 Data，计入 CRC）** | 由旧协议的小端改为大端并入 Data |
| 从机地址     | **保留设备地址（Unit ID，1 字节，帧首，计入 CRC）**              | 与旧协议的 Addr 字段一致        |
| 数据区字节序 | **大端**（Modbus 规定，高字节在前）                              | 由旧协议的小端改为大端          |
| 校验         | **Modbus CRC-16**（多项式 0xA001，初值 0xFFFF，低字节在前）      | 由「求和补码」换成标准 CRC-16   |
| 命令         | 参数组 **0x10–0x13**                                          | `Cmd` → `Function Code`        |
| 异常         | **沿用旧协议：**`0x02`** ACK + **`CP_ACK`** 错误码**             | 保留`CP_ACK` 枚举               |
| 承载通道     | **USB-HID，Report ID：主机→设备 `0x51`，设备→主机 `0x11`**      | 沿用旧协议的 HID 通道，不改 ID  |

### 帧起始与分帧

+ **取消起始符**：帧直接以 `Unit ID` 起始，不再有独立打头字节；`Len` 移到 `Func` 之后、归入 Data 段。
+ 分帧依赖 **USB-HID 报文边界**（一次 HID 传输即一帧）；纯串口透传时需由上层保证整帧边界。

---

## 二、帧结构

### 承载方式：USB-HID Report ID（0x51 / 0x11）

上下位机之间通过 **USB-HID** 通道承载本协议帧，Report ID 沿用现有 HID 自定义通道，不作更改：


| 方向        | Report ID | HID 报文（含 Report ID 首字节） | 一帧最大可承载长度 |
| ----------- | :-------: | ------------------------------- | ------------------ |
| 主机 → 设备 | `0x51`   | 64 B（1 B ID + 63 B 内容）      | 短帧一帧一报文     |
| 设备 → 主机 | `0x11`   | 64 B（1 B ID + 63 B 内容）      | 超 63 B 拆多报文   |

+ **Report ID 只属于 HID 层**：它是 HID 报文的第一个字节，**不计入 `Len`、也不参与 CRC-16**；Modbus 帧从 HID 报文的**第 2 个字节**（即 `Unit ID`）开始，按帧内 `Len` 取整帧长度。
+ 主机写参数时：`HID Write(0x51)` 的内容 = `UnitID + Func + Len + Data`（+ CRC）。
+ 设备响应时：`HID Read(0x11)` 的内容 = 同样的帧结构（含帧尾 CRC-16）。
+ 整帧总长超过单个 HID 报文承载能力（全速 64 B / 高速 1024 B）时，由**连续的多个 HID 报文按字节流续传**（仅首带 Report ID），接收端仍以 `Len` 与超时判定帧边界——与旧协议的分包方式一致，一帧不对应“一个报文”的强约束。

### 帧结构（Modbus 层）

帧格式：**Unit ID + Func + Len + Data + CRC-16**（**保留设备地址**；`Len` 归入 Data 段并计入 CRC）


| 偏移 | 字段        | 长度 | 是否计入 CRC | 说明                                                      |
| ---- | ----------- | ---- | :----------: | --------------------------------------------------------- |
| 0    | **UnitID**  | 1B   |      ✓      | 设备地址 / Modbus 从机地址（Slave Address，与旧协议一致） |
| 1    | **Func**    | 1B   |      ✓      | 功能码（Function Code）                                   |
| 2    | **LenHigh** | 1B   |      ✓      | 整帧总长高字节（**大端**，并入 Data，计入 CRC）           |
| 3    | **LenLow**  | 1B   |      ✓      | 整帧总长低字节                                            |
| 4 … | **Data**    | 可变 |      ✓      | Data 数据（**大端**）                                     |
| 末-1 | **CRCLo**   | 1B   |      —      | CRC-16 低字节（先发低字节）                               |
| 末   | **CRCHi**   | 1B   |      —      | CRC-16 高字节                                             |

### 长度字段 `Len`

Len 仍表示整帧总字节数；归入 Data 后采用 **16 位大端**（高字节在前）：

```plain
Len = 整帧总字节数 = Data字节数 + 6
      ( 6 = UnitID + Func + LenHigh + LenLow + CRCLo + CRCHi )
      Len 本身也属 CRC 覆盖范围（不再是不计 CRC 的外壳）
```

+ `Len` 为**私有长度字段**（旧协议无直接对应），标准 Modbus RTU 本身无长度字段；现并入 Data 且计入 CRC。

## 三、校验和（Modbus CRC-16）

+ 多项式：`0xA001`（0x8005 反射）；初值：`0xFFFF`；无最终亦或。
+ 计算对象：从帧首 `UnitID` 起至 `Data` 末字节（含 `Func`、`Len`），即 CRC 字段之前的所有字节。
+ 发送顺序：**低字节在前（CRCLo, CRCHi）**——与本项目现有帧尾字节序恰好一致，无需交换。

```c
uint16 ModbusCRC16(const uint8 *buf, uint16 len)
{
    uint16 crc = 0xFFFF;
    for (uint16 i = 0; i < len; i++)
    {
        crc ^= buf[i];
        for (uint8 b = 0; b < 8; b++)
        {
            if (crc & 0x0001) crc = (crc >> 1) ^ 0xA001;
            else              crc >>= 1;
        }
    }
    return crc;   // 发送时先发 (crc & 0xFF)，再发 (crc >> 8)
}
```

**示例**（0x10 随机写参数）：`00 10 00 0A 01 00 00 28` → CRC = `C8 29`（先发 `C8` 后发 `29`）。

## 四、功能码（Function Code）定义

功能码采用**参数访问组（0x10–0x13）**，复用旧协议原有 4 个参数操作函数。响应帧 `0x02` 维持不变。

### 参数访问组


| 功能码 | 名称                        | 方向 | 处理函数            | 原旧协议 CMD               |
| :----: | --------------------------- | :--: | ------------------- | -------------------------- |
|  0x10  | 随机写参数 Random Write     | **双向**  | `ComParamRandWrite` | 原`CC_PARAM_RAND_WR`(0x03) |
|  0x11  | 连续写参数 Sequential Write |  写  | `ComParamSequWrite` | 原`CC_PARAM_SEQU_WR`(0x05) |
|  0x12  | 随机读参数 Random Read      |  读  | `ComParamRandRead`  | 原`CC_PARAM_RAND_RD`(0x04) |
|  0x13  | 连续读参数 Sequential Read  |  读  | `ComParamSequRead`  | 原`CC_PARAM_SEQU_RD`(0x06) |

> **0x10 双向复用**：主机→设备为「随机写参数」；设备→主机为「参数主动上报」（如 MIC 电平、按键/Mute 状态变化），**帧结构与数据段格式完全相同**（`(Addr, Val)` 序列，同一套 `Len`/大端/CRC-16 规则）。因此上位机**不得按功能码做请求-响应配对**：收到 0x10 一律按「参数写入本地镜像」处理且不回 ACK；写命令的成功/失败确认只走 `0x02` ACK。

### 辅助功能码


| 功能码 | 名称       | 说明               |
| :----: | ---------- | ------------------ |
|  0x02  | 响应 / ACK | 保留`CC_ACK`(0x02) |

> ⚠ 注意：本方案赋予上述**自定义语义**，属「Modbus 风格」私有混合协议（仅保留 Len 私有外壳），**不与标准 Modbus 主机功能码语义互操作**。

## 五、数据段格式

> ⚠ 字节序：所有 16 位字段（地址、序号、数量、参数值）按 **大端（高字节在前）** 组织；`Len` 亦为 16 位大端（已并入 Data、计入 CRC）。写类命令成功后回 `0x02` ACK。以下数据段均指 **Modbus 帧的 Data 段**（不含 HID Report ID）。

### 参数访问组

#### 0x10 随机写参数（`ComParamRandWrite`）/ 设备主动上报

+ 数据段：`(Addr, Val)` 重复序列，每单元 4 字节，`len % 4 == 0`
  `Addr(Hi,Lo), Val(Hi,Lo), ...`
+ 主机→设备（写）：成功回 `0x02` ACK + `CP_ACK_NO_ERR`；`len % 4 != 0` 回 `CP_ACK_LEN_ERR`；地址超出参数表回 `CP_ACK_DATA_ERR`。
+ 设备→主机（上报）：**同一功能码、同一数据段格式**，上位机直接按 `(Addr, Val)` 更新本地镜像，**不需要也不应回 ACK**。

#### 0x11 连续写参数（`ComParamSequWrite`）

+ 请求数据段：`首地址(2B), 参数数目(2B), 数据(2B × N)`；校验 `Num*2 + 4 == len`
+ 响应：`0x02` ACK（长度不一致回 `CP_ACK_LEN_ERR`，地址超出参数表回 `CP_ACK_DATA_ERR`）

#### 0x12 随机读参数（`ComParamRandRead`）

+ 请求数据段：`地址(2B)` 序列，`len % 2 == 0`，`len*2 ≤ 512`
+ 响应数据段：`(Addr, Val)` 序列，每单元 4 字节，功能码回 `0x12`
+ 异常：`len % 2 != 0` 或超出单帧容量回 `CP_ACK_LEN_ERR`；任一地址超出参数表回 `CP_ACK_DATA_ERR`（不回半帧数据）

#### 0x13 连续读参数（`ComParamSequRead`）

+ 请求数据段：`首地址(2B), 参数数目(2B)`（固定 4 字节）
+ 响应数据段：`首地址(2B), 数目(2B), 数据(2B × N)`（`ComTxPacket2` 大包），功能码回 `0x13`
+ 异常：`len != 4` 或超出单帧容量回 `CP_ACK_LEN_ERR`；读区间越界回 `CP_ACK_DATA_ERR`

### 参数访问组报文示例

> 统一约定：帧顺序 `UnitID+Func+Len+Data`；Unit ID=`00`；`Len=数据+6`（16 位大端，并入 Data）；数据段 16 位字段**大端**；CRC-16 覆盖 `UnitID+Func+Len+Data`，低字节先发。写类命令成功后均回同一帧 `0x02` ACK：`00 02 00 08 00 00 F8 19`；读类命令响应**回显原功能码**。


| 功能码 | 场景                                    | 请求帧（Hex）                               | 响应帧（Hex）                               |
| :----: | --------------------------------------- | ------------------------------------------- | ------------------------------------------- |
|  0x10  | 写 addr`0x0100`=0x0028                  | `00 10 00 0A 01 00 00 28 C8 29`             | `00 02 00 08 00 00 F8 19`                   |
|  0x11  | 从`0x0100` 连续写 2 个值(0x0001,0x0002) | `00 11 00 0E 01 00 00 02 00 01 00 02 10 53` | `00 02 00 08 00 00 F8 19`                   |
|  0x12  | 随机读 addr`0x0100`、`0x0101`           | `00 12 00 0A 01 00 01 01 2B A7`             | `00 12 00 0E 01 00 00 28 01 01 00 50 86 D0` |
|  0x13  | 从`0x0100` 连续读 2 个                  | `00 13 00 0A 01 00 00 02 7A F6`             | `00 13 00 0E 01 00 00 02 00 01 00 02 1B EB` |
|  0x10  | **设备主动上报**（MIC 电平 `0x2057`=0，设备→主机） | —（非请求帧）                         | `00 10 00 0A 20 57 00 00 73 DB`             |

> 读响应数据段含义：0x12 回 `(Addr,Val)` 序列；0x13 回 `首址,数目,数据...`。

> ⚠ **参数地址有效范围**（本机 M001）：地址高 4 位为块选择（`MEM_ADDR_TYPE_MASK = 0xF000`），低 12 位为块内偏移：
>
> | 地址段 | 含义 | 有效范围 |
> | ------ | ---- | -------- |
> | `0x0xxx` | Device Info | `0x0000 ~ 0x003D`（共 62 项） |
> | `0x1xxx` | Config | `0x1000 ~ 0x100D`（共 14 项） |
> | `0x2xxx` | 当前预设 | `0x2000 ~ 0x2075`（共 118 项） |
> | `0x3xxx` | 用户预设（Preset1） | 按预设号选块 |
>
> 上表示例中的 `0x0100`/`0x0101` **仅为帧格式示意，本机为无效地址**，下位机会回 `CP_ACK_DATA_ERR`；实际读写请用上述有效区间。

## 六、异常响应（沿用旧协议）

不使用 Modbus 的 `Func | 0x80` 异常机制；**沿用旧协议**：出错时下发一帧 `0x02`（`CC_ACK`）响应，数据段为 **2 字节 **`CP_ACK`** 错误码**；成功时同样回 `0x02` + `CP_ACK_NO_ERR`。由 `ComTxAck(err)` 发送，与旧协议原实现一致。


| 错误码 | 宏                     | 含义                       |
| ------ | ---------------------- | -------------------------- |
| 0x0000 | `CP_ACK_NO_ERR`        | 无错误（成功）             |
| 0x0001 | `CP_ACK_DEV_ADDR_ERR`  | 设备地址不匹配             |
| 0x0002 | `CP_ACK_LEN_ERR`       | 长度错误（超一帧最大容量） |
| 0x0003 | `CP_ACK_CHECKSUM_ERR`  | 校验和（CRC）错误          |
| 0x0004 | `CP_ACK_READ_ONLY_ERR` | 参数只读                   |
| 0x0005 | `CP_ACK_DATA_ERR`      | 参数值或参数地址超范围 / 不合理  |

+ 地址不匹配、CRC 错误等**均回 **`0x02`** ACK 携带对应错误码**（与标准 Modbus 的静默丢弃不同）。
+ **下位机不得静默不回包**：参数访问组（0x10–0x13）的每一条请求，要么回数据帧（读类）、要么回 `0x02` ACK（写类成功 / 任意异常），不存在“收到但不应”的情况，上位机可统一靠超时判定通讯异常。具体映射：


| 场景                       | 错误码          |
| -------------------------- | --------------- |
| `Len` 字段本身非法（<6 或超缓存） | `CP_ACK_LEN_ERR`   |
| 数据段长度与功能码要求不符（如 0x10 的 `len%4`、0x11 的 `Num*2+4`、0x12 的 `len%2`、0x13 的 `len!=4`） | `CP_ACK_LEN_ERR`   |
| 读/写地址或区间超出参数表有效范围 | `CP_ACK_DATA_ERR`  |

### 异常响应示例

> 约定：帧顺序 `UnitID+Func+Len+Data`；Unit ID = `00`；错误码为 16 位**大端**（`ErrHi, ErrLo`，本表高字节恒为 `00`）；`Len` 亦为大端并入 Data；CRC-16 覆盖 `UnitID + Func + Len + Data`，**低字节先发**；ACK 帧数据 2 字节 → `Len = 0x0008`。


| 场景         | CP_ACK                          | 完整帧（Hex）             |
| ------------ | ------------------------------- | ------------------------- |
| 成功确认     | `CP_ACK_NO_ERR` (0x0000)        | `00 02 00 08 00 00 F8 19` |
| 设备地址错误 | `CP_ACK_DEV_ADDR_ERR` (0x0001)  | `00 02 00 08 00 01 39 D9` |
| 长度错误     | `CP_ACK_LEN_ERR` (0x0002)       | `00 02 00 08 00 02 79 D8` |
| 校验和错误   | `CP_ACK_CHECKSUM_ERR` (0x0003)  | `00 02 00 08 00 03 B8 18` |
| 写只读参数   | `CP_ACK_READ_ONLY_ERR` (0x0004) | `00 02 00 08 00 04 F9 DA` |
| 参数值超范围 | `CP_ACK_DATA_ERR` (0x0005)      | `00 02 00 08 00 05 38 1A` |

**字段拆解**（以“参数值超范围”帧为例）：

```plain
00        Unit ID
02        Func = CC_ACK
00 08     Len = 0x0008（总帧长 8 = 数据 2 + 6，大端）
00 05     CP_ACK_DATA_ERR（大端 ErrHi,ErrLo）
38 1A     CRC-16（Lo,Hi，覆盖 UnitID+Func+Len+Data = 00 02 00 08 00 05）
```

> 上述 8 字节为 Modbus 帧本身；在 USB-HID 上实际下发/上报时，报文首字节还要加上 Report ID（主机→设备 `0x51`，设备→主机 `0x11`），即该 ACK 在 HID 读报文中的完整内容为 `11 00 02 00 08 00 05 38 1A`（共 9 B，前 1 B 为 ID，不计长度与校验）。

## 七、接收状态机（沿用旧协议状态集，按新帧序重排）

沿用旧协议 `RX_STATE` 的状态集；因帧序改为 `UnitID→Func→Len→Data`，入帧顺序相应重排：

```plain
ADDR(UnitID) → CMD(Func) → LEN_HIGH → LEN_LOW → DATA_CRC → (一帧完成)
```

状态集沿用旧协议，仅重排入帧顺序并取消起始符：


| 状态       | 旧协议现行为                        | 本协议调整                                                                         |
| ---------- | ----------------------------------- | ---------------------------------------------------------------------------------- |
| `BEGIN`    | 等待固定`0xC4`                      | **取消起始符**：去掉 HID Report ID（`0x51`）后的帧首字节即 Unit ID（由 `ADDR` 处理）  |
| `ADDR`     | 仅接受`0x00`，否则回 `DEV_ADDR_ERR` | 接受本机配置的 Unit ID（示例`0x00`，与旧协议一致）；失配则回 `CP_ACK_DEV_ADDR_ERR` |
| `CMD`      | 记录 Cmd，`crcCalc` 从 Begin 起累加 | 记录 Func；**CRC 从帧首 UnitID 起累加，覆盖 UnitID+Func+Len+Data**                 |
| `DATA_CRC` | 求和补码比对                        | 换成**CRC-16(0xA001)** 比对，CRCLo 在前                                            |

超时保护（`Timeout=300` / `TFB_HID_RX_TO`）与缓冲上限保持不变。

> 注：`ADDR` 状态**保留**（对应设备地址 / Unit ID），状态机跳转与旧协议完全一致。

## 八、通信流向示意

```plain
                  HID Write Report ID = 0x51
上位机  ──[0x51]|[UnitID|Func|Len|Data(大端)|CRC-16]──►  下位机
                                                    │ 去 Report ID 后入环形缓冲
                                                    │ 状态机解帧 + CRC-16 校验
                                                    │ ComFuncEntry 按功能码分发
                                                    ▼
                  HID Read Report ID = 0x11
上位机  ◄──[0x11]|[UnitID|Func|Len|Data|CRC-16]────────  正常响应
上位机  ◄──[0x11]|[UnitID|0x02|Len|ErrCode(2B)|CRC-16]───  异常/ACK 响应
```

> `[0x51]` / `[0x11]` 为 HID 报文的 Report ID 首字节，属传输层，不计入 `Len` 与 CRC-16。
