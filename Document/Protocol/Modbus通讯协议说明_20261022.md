# Modbus 通讯协议说明（旧协议框架改造版）

> **v0.2 修订（2026-10-24，依据嵌入式工程师答复）**
>
> 1. **删除附录 A「效果器控制组 0x03–0x08」**：该组是自定义示例协议，不是设备真实协议。参数一律按《M001参数表V0.1.xlsx》的**寄存器地址**经 `0x10–0x13` 访问，本协议不再定义效果器级的 `EFFECT_ID / SEG / ParamIdx`。
> 2. **更正 CRC 示例**：`11 03 00 2B 00 01` 的 CRC 为 `F6 92`（原文误写 `CD 61`）。
> 3. **补充分帧规则**：HID 报文 64 字节，单帧上限 512 字节（下位机接收缓冲），一帧可跨多个报文，接收方按 `Len` 重组。
> 4. **补充字符串字段编码与参数标定摘要**（新增附录 A）。
> 5. **明确 EQ 开放范围**：只对上位机开放 7 段，其余段为 DSP 内部参数，无寄存器。

## 一、总体设计


| 维度         | 取值                                                             | 与旧协议的关系                  |
| ------------ | ---------------------------------------------------------------- | ------------------------------- |
| 帧起始       | **去掉 **`0xC4`** 起始符，帧直接以 **`Unit ID`** 起始**          | 帧边界由 `Len` 界定（可跨报文） |
| 长度字段     | **保留 **`Len`**（16 位大端，移到 Func 后并入 Data，计入 CRC）** | 由旧协议的小端改为大端并入 Data |
| 从机地址     | **保留设备地址（Unit ID，1 字节，帧首，计入 CRC）**              | 与旧协议的 Addr 字段一致        |
| 数据区字节序 | **大端**（Modbus 规定，高字节在前）                              | 由旧协议的小端改为大端          |
| 校验         | **Modbus CRC-16**（多项式 0xA001，初值 0xFFFF，低字节在前）      | 由「求和补码」换成标准 CRC-16   |
| 命令         | 参数组 **0x10–0x13** + 响应 **0x02**                            | `Cmd` → `Function Code`        |
| 异常         | **沿用旧协议：**`0x02`** ACK + **`CP_ACK`** 错误码**             | 保留`CP_ACK` 枚举               |

### 帧起始与分帧

+ **取消起始符**：帧直接以 `Unit ID` 起始，不再有独立打头字节；`Len` 移到 `Func` 之后、归入 Data 段。
+ **报文 ≠ 帧**：USB-HID 报文固定 **64 字节**；一帧可占 1~8 个报文，接收方**按 `Len` 重组**，不依赖报文边界。
+ **单帧上限 512 字节**（= 下位机接收缓冲 8 × 64）；超出回 `CP_ACK_LEN_ERR`。
+ 报文内不足一帧时尾部补 `0x00` 填充，接收方以 `Len` 判定帧尾，填充字节忽略。
+ 纯串口透传时需由上层按 `Len` 切帧。

## 二、帧结构

帧格式：**Unit ID + Func + Len + Data + CRC-16**（**保留设备地址**；`Len` 归入 Data 段并计入 CRC）


| 偏移 | 字段        | 长度 | 是否计入 CRC | 说明                                                      |
| ---- | ----------- | ---- | :----------: | --------------------------------------------------------- |
| 0    | **UnitID**  | 1B   |      ✓      | 设备地址 / Modbus 从机地址（Slave Address，与旧协议一致） |
| 1    | **Func**    | 1B   |      ✓      | 功能码（Function Code）                                   |
| 2    | **LenHigh** | 1B   |      ✓      | 整帧总长高字节（**大端**，并入 Data，计入 CRC）           |
| 3    | **LenLow**  | 1B   |      ✓      | 整帧总长低字节                                            |
| 4 … | **Data**    | 可变 |      ✓      | Data 数据（**大端**）                                     |
| 末-1 | **CRCLo**   | 1B   |      —      | CRC-16 低字节（先发低字节）                               |
| 末   | **CRCHi**   | 1B   |      —      | CRC-16 高字节                                             |

### 长度字段 `Len`

Len 仍表示整帧总字节数；归入 Data 后采用 **16 位大端**（高字节在前）：

```plain
Len = 整帧总字节数 = Data字节数 + 6
      ( 6 = UnitID + Func + LenHigh + LenLow + CRCLo + CRCHi )
      Len 本身也属 CRC 覆盖范围（不再是不计 CRC 的外壳）
```

+ `Len` 为**私有长度字段**（旧协议无直接对应），标准 Modbus RTU 本身无长度字段；现并入 Data 且计入 CRC。

## 三、校验和（Modbus CRC-16）

+ 多项式：`0xA001`（0x8005 反射）；初值：`0xFFFF`；无最终亦或。
+ 计算对象：从帧首 `UnitID` 起至 `Data` 末字节（含 `Func`、`Len`），即 CRC 字段之前的所有字节。
+ 发送顺序：**低字节在前（CRCLo, CRCHi）**——与本项目现有帧尾字节序恰好一致，无需交换。

```c
uint16 ModbusCRC16(const uint8 *buf, uint16 len)
{
    uint16 crc = 0xFFFF;
    for (uint16 i = 0; i < len; i++)
    {
        crc ^= buf[i];
        for (uint8 b = 0; b < 8; b++)
        {
            if (crc & 0x0001) crc = (crc >> 1) ^ 0xA001;
            else              crc >>= 1;
        }
    }
    return crc;   // 发送时先发 (crc & 0xFF)，再发 (crc >> 8)
}
```

**CRC 自检向量**（标准 Modbus 读保持寄存器帧，**无 `Len` 字段，只能验算法、不能当本协议帧用**）：`11 03 00 2B 00 01` → CRC = `F6 92`（先发 `F6` 后发 `92`）。
若要用本协议真实帧自检，用 ACK 帧 `00 02 00 08 00 00 F8 19`（CRC 覆盖前 6 字节 `00 02 00 08 00 00`，结果 `F8 19`）。

## 四、功能码（Function Code）定义

功能码只有一组：**参数访问组（0x10–0x13）**，复用旧协议原有 4 个参数操作函数；响应帧 `0x02` 维持不变。

参数一律通过**寄存器地址**访问，地址、范围、步进、默认值与读写权限见《M001参数表V0.1.xlsx》，标定换算见文末《附录 A》。本协议**不定义**效果器级的 `EFFECT_ID / SEG / ParamIdx`。

### 参数访问组


| 功能码 | 名称                        | 方向 | 处理函数            | 原旧协议 CMD               |
| :----: | --------------------------- | :--: | ------------------- | -------------------------- |
|  0x10  | 随机写参数 Random Write     |  写  | `ComParamRandWrite` | 原`CC_PARAM_RAND_WR`(0x03) |
|  0x11  | 连续写参数 Sequential Write |  写  | `ComParamSequWrite` | 原`CC_PARAM_SEQU_WR`(0x05) |
|  0x12  | 随机读参数 Random Read      |  读  | `ComParamRandRead`  | 原`CC_PARAM_RAND_RD`(0x04) |
|  0x13  | 连续读参数 Sequential Read  |  读  | `ComParamSequRead`  | 原`CC_PARAM_SEQU_RD`(0x06) |

### 辅助功能码


| 功能码 | 名称       | 说明               |
| :----: | ---------- | ------------------ |
|  0x02  | 响应 / ACK | 保留`CC_ACK`(0x02) |

> ⚠ 注意：`0x02`（标准 Modbus 为 Read Discrete Inputs）与 `0x10–0x13` 均不复用标准 Modbus 语义，属「Modbus 风格」私有混合协议（仅保留 Len 私有外壳），**不与标准 Modbus 主机功能码语义互操作**。

## 五、数据段格式

> ⚠ 字节序：所有 16 位字段（地址、数量、参数值）按 **大端（高字节在前）** 组织；`Len` 亦为 16 位大端（已并入 Data、计入 CRC）。**字符串字段**按 16 位字大端存放（每字高字节为前一个字符，如 `"JY"` → `0x4A59`），右补 `0x00`。写类命令成功后回 `0x02` ACK。整帧 ≤ 512 字节，超出回 `CP_ACK_LEN_ERR`。

### 参数访问组

#### 0x10 随机写参数（`ComParamRandWrite`）

+ 请求数据段：`(Addr, Val)` 重复序列，每单元 4 字节，`len % 4 == 0`
  `Addr(Hi,Lo), Val(Hi,Lo), ...`
+ 响应：`0x02` ACK

#### 0x11 连续写参数（`ComParamSequWrite`）

+ 请求数据段：`首地址(2B), 参数数目(2B), 数据(2B × N)`；校验 `Num*2 + 4 == len`
+ 响应：`0x02` ACK

#### 0x12 随机读参数（`ComParamRandRead`）

+ 请求数据段：`地址(2B)` 序列，`len % 2 == 0`；响应数据段 `4 × 地址数 ≤ 512`，即一次最多读 **126** 个参数
+ 响应数据段：`(Addr, Val)` 序列，每单元 4 字节，功能码回 `0x12`

#### 0x13 连续读参数（`ComParamSequRead`）

+ 请求数据段：`首地址(2B), 参数数目(2B)`
+ 响应数据段：`首地址(2B), 数目(2B), 数据(2B × N)`（`ComTxPacket2` 大包，可跨报文），功能码回 `0x13`；`N ≤ 251`（`10 + 2N ≤ 512`）

### 参数访问组报文示例

> 统一约定：帧顺序 `UnitID+Func+Len+Data`；Unit ID=`00`；`Len=数据+6`（16 位大端，并入 Data）；数据段 16 位字段**大端**；CRC-16 覆盖 `UnitID+Func+Len+Data`，低字节先发。写类命令成功后均回同一帧 `0x02` ACK：`00 02 00 08 00 00 F8 19`；读类命令响应**回显原功能码**。下表改用**真实寄存器地址**（`0x2000` 起为当前预设区）。


| 功能码 | 场景                                            | 请求帧（Hex）                                     | 响应帧（Hex）                                     |
| :----: | ----------------------------------------------- | ------------------------------------------------- | ------------------------------------------------- |
|  0x10  | 写 `0x2024`（降噪开关）= 1                      | `00 10 00 0A 20 24 00 01 43 C0`                   | `00 02 00 08 00 00 F8 19`                         |
|  0x11  | 从 `0x205B` 连续写 2 个值(0x0001, 0x0002)       | `00 11 00 0E 20 5B 00 02 00 01 00 02 39 42`       | `00 02 00 08 00 00 F8 19`                         |
|  0x12  | 随机读 `0x205B`、`0x205C`                       | `00 12 00 0A 20 5B 20 5C 89 E1`                   | `00 12 00 0E 20 5B 00 00 20 5C 00 32 D5 C0`       |
|  0x13  | 从 `0x2000` 连续读 2 个                         | `00 13 00 0A 20 00 00 02 70 CA`                   | `00 13 00 0E 20 00 00 02 00 00 00 01 C9 FE`       |

> 读响应数据段含义：0x12 回 `(Addr,Val)` 序列；0x13 回 `首址,数目,数据...`。

## 六、异常响应（沿用旧协议）

不使用 Modbus 的 `Func | 0x80` 异常机制；**沿用旧协议**：出错时下发一帧 `0x02`（`CC_ACK`）响应，数据段为 **2 字节 **`CP_ACK`** 错误码**；成功时同样回 `0x02` + `CP_ACK_NO_ERR`。由 `ComTxAck(err)` 发送，与旧协议原实现一致。


| 错误码 | 宏                     | 含义                       |
| ------ | ---------------------- | -------------------------- |
| 0x0000 | `CP_ACK_NO_ERR`        | 无错误（成功）             |
| 0x0001 | `CP_ACK_DEV_ADDR_ERR`  | 设备地址不匹配             |
| 0x0002 | `CP_ACK_LEN_ERR`       | 长度错误（超一帧最大容量） |
| 0x0003 | `CP_ACK_CHECKSUM_ERR`  | 校验和（CRC）错误          |
| 0x0004 | `CP_ACK_READ_ONLY_ERR` | 参数只读                   |
| 0x0005 | `CP_ACK_DATA_ERR`      | 参数值超范围 / 不合理      |

+ 地址不匹配、CRC 错误等**均回 **`0x02`** ACK 携带对应错误码**（与标准 Modbus 的静默丢弃不同）。

### 异常响应示例

> 约定：帧顺序 `UnitID+Func+Len+Data`；Unit ID = `00`；错误码为 16 位**大端**（`ErrHi, ErrLo`，本表高字节恒为 `00`）；`Len` 亦为大端并入 Data；CRC-16 覆盖 `UnitID + Func + Len + Data`，**低字节先发**；ACK 帧数据 2 字节 → `Len = 0x0008`。


| 场景         | CP_ACK                          | 完整帧（Hex）             |
| ------------ | ------------------------------- | ------------------------- |
| 成功确认     | `CP_ACK_NO_ERR` (0x0000)        | `00 02 00 08 00 00 F8 19` |
| 设备地址错误 | `CP_ACK_DEV_ADDR_ERR` (0x0001)  | `00 02 00 08 00 01 39 D9` |
| 长度错误     | `CP_ACK_LEN_ERR` (0x0002)       | `00 02 00 08 00 02 79 D8` |
| 校验和错误   | `CP_ACK_CHECKSUM_ERR` (0x0003)  | `00 02 00 08 00 03 B8 18` |
| 写只读参数   | `CP_ACK_READ_ONLY_ERR` (0x0004) | `00 02 00 08 00 04 F9 DA` |
| 参数值超范围 | `CP_ACK_DATA_ERR` (0x0005)      | `00 02 00 08 00 05 38 1A` |

**字段拆解**（以“参数值超范围”帧为例）：

```plain
00        Unit ID
02        Func = CC_ACK
00 08     Len = 0x0008（总帧长 8 = 数据 2 + 6，大端）
00 05     CP_ACK_DATA_ERR（大端 ErrHi,ErrLo）
38 1A     CRC-16（Lo,Hi，覆盖 UnitID+Func+Len+Data = 00 02 00 08 00 05）
```

**请求→响应配对示例**（成功）：上位机写 `0x2024`（降噪开关）= 1

```plain
请求: 00 10 00 0A 20 24 00 01 43 C0   // Unit=00 Func=0x10 随机写, Addr=0x2024, Val=0x0001
响应: 00 02 00 08 00 00 F8 19         // CP_ACK_NO_ERR
```

> 若写入只读寄存器（如 `0x2023` MIC Gain），请求 `00 10 00 0A 20 23 00 01 F2 01`，响应为 `00 02 00 08 00 04 F9 DA`（`CP_ACK_READ_ONLY_ERR`）。
> 若写入值超范围（如 `0x2024` 写 2），响应为 `00 02 00 08 00 05 38 1A`（`CP_ACK_DATA_ERR`）。

## 七、接收状态机（沿用旧协议状态集，按新帧序重排）

沿用旧协议 `RX_STATE` 的状态集；因帧序改为 `UnitID→Func→Len→Data`，入帧顺序相应重排：

```plain
ADDR(UnitID) → CMD(Func) → LEN_HIGH → LEN_LOW → DATA_CRC → (一帧完成)
```

状态集沿用旧协议，仅重排入帧顺序并取消起始符：


| 状态       | 旧协议现行为                        | 本协议调整                                                                         |
| ---------- | ----------------------------------- | ---------------------------------------------------------------------------------- |
| `BEGIN`    | 等待固定`0xC4`                      | **取消起始符**：帧首字节即 Unit ID（由 `ADDR` 处理）                               |
| `ADDR`     | 仅接受`0x00`，否则回 `DEV_ADDR_ERR` | 接受本机配置的 Unit ID（示例`0x00`，与旧协议一致）；失配则回 `CP_ACK_DEV_ADDR_ERR` |
| `CMD`      | 记录 Cmd，`crcCalc` 从 Begin 起累加 | 记录 Func；**CRC 从帧首 UnitID 起累加，覆盖 UnitID+Func+Len+Data**                 |
| `DATA_CRC` | 求和补码比对                        | 换成**CRC-16(0xA001)** 比对，CRCLo 在前                                            |

超时保护（`Timeout=300` / `TFB_HID_RX_TO`，单位 ms）与**接收缓冲 512 字节**保持不变；单帧超 512 字节回 `CP_ACK_LEN_ERR`。

> 注：`ADDR` 状态**保留**（对应设备地址 / Unit ID），状态机跳转与旧协议完全一致。

## 八、通信流向示意

```plain
上位机  ──[UnitID|Func|Len|Data(大端)|CRC-16]──►  下位机
                                                            │ 状态机解帧 + CRC-16 校验
                                                            │ ComFuncEntry 按功能码分发
                                                            ▼
上位机  ◄──[UnitID|Func|Len|Data|CRC-16]──  正常响应
上位机  ◄──[UnitID|0x02|Len|ErrCode(2B)|CRC-16]───  异常/ACK 响应
```

## 附录 A：参数地址、标定与开放范围（摘要）

> **权威源**：《M001参数表V0.1.xlsx》。本附录只是给上位机实现看的换算速查，参数表更新后以参数表为准。
> 本附录替代原「效果器控制协议（0x03–0x08）」——那一组是自定义示例协议，不是设备真实协议。

### A.1 地址分区

| 区段     | 范围              | 内容                                                                                       | 权限                  |
| -------- | ----------------- | ------------------------------------------------------------------------------------------ | --------------------- |
| 设备信息 | `0x0000–0x003D`   | 机型码、设备名、固件版本/类型、DSP 版本、VID/PID、生产日期、SN                             | 只读                  |
| 设备配置 | `0x1000–0x100D`   | 心跳、设备地址、预设总数/启动/保存/加载/删除、通讯错误、DFU、重初始化、恢复出厂、同步标志   | 读写                  |
| 当前预设 | `0x2000–0x2071`   | 校验和、有效标志、预设名、MIC/HP 开关与增益、ENC、EQ 模式与 7 段、Comp、Limit、电平、NoiseGate、3BandDrc | 读写（标只读者除外） |

> 字符串字段（机型码、设备名、SN、预设名）按 16 位字**大端**存放（每字高字节为前一个字符）。参数表中现有示例值仍是字内小端，待参数表统一。

### A.2 标定式（`value` = 实际值，`param` = 寄存器原始值）

| 标定式               | 适用参数（地址）                                                                                     |
| -------------------- | ---------------------------------------------------------------------------------------------------- |
| `param`（直通）      | MIC/HP 开关与增益、ENC 开关/强度、EQ 模式与 Band-Enable/Type/Freq、NoiseGate attack/release/knee/hp_freq、3BandDrc fc1/fc2/attackTime/releaseTime、MIC 电平 |
| `param × 0.1 − 32`   | EQ Gain（自 `0x202A` 起每段 +5），`param` 0–440                                                      |
| `param / 10`         | EQ Q（每段 +5）、Comp/Limit MakeUpGain/Rate/KneeWidth                                                |
| `(param − 600) / 10` | Comp/Limit Threshold，`param` 0–600                                                                  |
| `param / 10000`      | Comp/Limit Attack、Release（单位 s），`param` 1–2000 / 50–20000                                      |
| `param − 91`         | NoiseGate `threshold_db`，`param` 0–91                                                               |
| `param / 1000`       | NoiseGate `ratio`，`param` 50–999                                                                    |
| `param / 100`        | 3BandDrc `preGain`，`param` 0–400                                                                    |
| `(param − 800) / 10` | 3BandDrc `threshold`，`param` 0–800                                                                  |
| **待补**             | 3BandDrc `ratio`（`0x2067` / `0x206C` / `0x2071`）：参数表备注为空，范围 1–20、步进 0.1；若沿用 `/10` 则为 `param` 10–200 |

### A.3 开放范围与顺序约定

+ **EQ 只开放 7 段**：`Band-1 … Band-7` 占 `0x2027–0x2049`（每段 5 字：Enable / Type / Freq / Gain / Q）。另外 7 段是 DSP 内部调音参数，**没有寄存器，上位机既不能读也不能写**。
+ **Gain 只读**：`0x2023` MIC Gain、`0x205A` HP 音量为只读，写入回 `CP_ACK_READ_ONLY_ERR`。
+ **3BandDrc 顺序是「低 → 高 → 中」**：`0x2061` fc1、`0x2062` fc2，随后 `0x2063–0x2067`（`freq < fc1`）、`0x2068–0x206C`（`freq > fc2`）、`0x206D–0x2071`（`fc1 < freq < fc2`）；每段 5 项依次是 preGain / threshold / attackTime / releaseTime / **ratio**。
+ **`0x2024` / `0x2025`**：参数表中这两行出现了两组定义（序号都是 36/37：一组「降噪开关/降噪强度」，一组「监听开关/HP 音量」）。按「参数随表向下推进、地址逐行递增」的原则，**以降噪组为准**，监听以 `0x2059` / `0x205A` 为准；重复行待参数表 v0.2 删除。
