## 5. 过程记录与偏差说明（便于复核）

1. **基线冻结有效**：快照 582/582 哈希一致；冻结期另一会话的并发改动没有进入判定对象。O1（`typecheck` 两次结果相反）在快照上连跑 3 次全过，确认是并发写入的瞬时现象。
2. **快照内执行 `pnpm run` 的适配**：`node_modules` 是指向仓库的目录联接，pnpm 11 的依赖状态检查会尝试 `pnpm install` 并因无 TTY 失败。统一加 `--config.verify-deps-before-run=false`（只影响命令执行方式，不改产物、不改配置）；工作树 Final Run 用同一方式复跑，结果一致。该适配已记录在 `问题清单.md` 自决区新增条目。
3. **打包冒烟的启动方式**：ShellExecute 被本机安全警告阻塞，改用 `CreateProcess`（`UseShellExecute=false`）启动同一 exe 取证；N8 判“阻塞（双击路径）”，产物本体通过。理由与证据见 `验收报告.md` §2 与 §6。
4. **测试资产调整**：U/R/V 三支探针在调试中修正了断言口径（详见 `缺陷清单.md` §4），属 S13 允许范围；**产品代码一行未改**，因此没有触发 S4 的“修复 → 快照复测”流程。
5. **DFU 免测**：按 Q6 未做任何实刷/救砖/界面刷写；`tests/unit/dfu/**` 的既有用例仍随 G2 执行并通过（覆盖率也包含 `device/dfu/**`）。
6. **真机状态**：R12 已把可写参数还原为 V0.3 默认值并以裸 HID 回读证明 0 失配；追加耐久结束后再次还原并回读 0 失配；设备当前为 MainApp、固件 0.0.6.0。
7. **追加测试的两处口径**：① 耐久进程内存用外部 PowerShell 按 `--remote-debugging-port` 采样（脚本内置采样属性名写错，已修为 `WorkingSetSize`，本轮数据以外部 13 次采样为准）；② 耐久每 15 min 截图有 3/9 次 `Page.captureScreenshot` 超时（高负载阶段），最终截图与关键阶段截图齐全，属取证缺口不属产品问题。
8. **界面审核未改产品代码**：4 条 P2 都是文案宽度/是否允许两行/tooltip 的产品口径选择，先出审核与建议，等你定口径再改 CSS 并复测（S4 流程）。
