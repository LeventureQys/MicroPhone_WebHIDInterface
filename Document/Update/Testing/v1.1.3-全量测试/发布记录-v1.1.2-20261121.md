## 2. 构建命令

```powershell
$env:ELECTRON_MIRROR = 'https://npmmirror.com/mirrors/electron/'
$env:ELECTRON_BUILDER_BINARIES_MIRROR = 'https://npmmirror.com/mirrors/electron-builder-binaries/'
Remove-Item Env:ELECTRON_RUN_AS_NODE -ErrorAction SilentlyContinue
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\dist.ps1 -SkipSmoke
```

- `dist.ps1` 内含：类型检查（tsc --noEmit）→ 单测（vitest，50 文件 / 732 例）→ `electron-vite build` → `electron-builder --win portable` → 产物校验 → `build-info.txt` / `使用说明.txt`。
- 本机冒烟用 `CreateProcess`（`UseShellExecute=false`）单独执行，原因见 §4；因此 `dist.ps1` 带 `-SkipSmoke`（否则 ShellExecute 会被系统“打开文件 - 安全警告”阻塞）。

## 4. 怎么用（一键启动）

### 4.1 本机（Chromium 沙箱受限）——请双击快捷方式

1. 进入 `release\` 目录，**双击 `MIC STUDIO.exe`**（一键启动器，自动带 `--no-sandbox`；已用资源管理器双击实测出窗口）。备选：双击 `双击这里启动 MIC STUDIO.lnk`。
2. 插上 M001（`USB\VID_0A67&PID_0010`），启动后自动连接并同步参数；配置与日志在 exe 同级 `MicStudioData\`。
3. 第一次启动可能 15–20 秒才出窗口：portable 正在往 `%TEMP%` 解包，属正常。

### 4.2 为什么直接双击 exe 没反应（已实测复现）

| 启动方式 | 结果 |
|---|---|
| 直接双击 `MicStudio-1.1.2-portable.exe`（无参数，CreateProcess） | **5.7 s 后静默退出，退出码 `0x80000003`（-2147483645），无窗口、不生成 `startup.log`** |
| 带 `--no-sandbox` 启动 | **6.2 s 出窗口** `MIC STUDIO`，`startup.log` 正常 |
| 资源管理器双击 `双击这里启动 MIC STUDIO.lnk` | **出窗口 `MIC STUDIO`**（本机实测，pid 已记入发布验证） |
| 通过“打开文件 - 安全警告”点“运行”/DSH 卡片“运行”按钮 | 与直接双击 exe 等价（不带参数），同样会静默退出 |

**原因**：本机 Chromium 的 GPU/沙箱子进程受策略限制（`AGENTS.md` 已知坑 14 / 18），不带 `--no-sandbox` 时 Electron 还没写日志就退出；**不是安装包损坏**。目标机若 Chromium 沙箱正常，直接双击 exe 也可用。

**为什么不能让 exe 自己补参数**：实测不带 `--no-sandbox` 时，Electron 在进入主进程 JS 之前就退出（连一个标记文件都写不出来），所以 `app.commandLine.appendSwitch('no-sandbox')` 或主进程内自我重启都来不及执行——参数必须出现在**进程启动命令行**上。`MIC STUDIO.exe` 就是 28 KB 的启动器：用 `CreateProcess` 把 `--no-sandbox` 加到 payload 命令行上，双击它即可。

**启动器复现**：源码 `scripts/launcher/MicStudioLauncher.cs`，编译脚本 `scripts/build-launcher.ps1`（`csc /target:winexe /win32icon:build/icon.ico`）。
