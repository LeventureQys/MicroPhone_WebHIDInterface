## 1. 测试架构与分层

### 1.1 六层结构

```
L6 打包冒烟        dist.ps1 + Start-Process(portable)        → G6/G7、N6/N8
L5 裸 HID 探针     python ctypes（tools/dfu + real* .py）    → R1/R5/R12、P1 真值侧
L4 真实界面 CDP    Electron --remote-debugging-port + 探针   → U1–U17、R2/R3/R6–R11、S1/S3/S5
L3 虚拟下位机      tools/vdevice（桥 8765 + 侧车 8766）      → G5、V1–V4、P5/P6/P8 的行为侧
L2 单测 + 覆盖率   vitest（50 文件 / happy-dom）             → G2/G3、N2/N3、P3/P4/P7 的算法侧
L1 静态门禁        tsc --noEmit + electron-vite build        → G1/G4、N1/N4
```

### 1.2 每层「测什么 / 为什么需要 / 不测会漏什么」

| 层 | 测什么 | 为什么需要（不可替代性） | 不测会漏什么 |
|---|---|---|---|
| **L1 静态门禁** | 类型正确性（`tsconfig.json` include 范围：`src/**`、`tests/**`、`vitest.config.ts`）、三端可构建（`out/main` / `out/preload` / `out/renderer`） | 只有它能证明"代码能被编译成可交付产物"；单测跑的是 vite 转换后的模块，不做跨文件类型检查 | 类型漂移（如 i18n 三键缺失，正是 O1 的现象）、preload 路径错、产物缺失导致后续所有层无对象可测 |
| **L2 单测 + 覆盖率** | `tests/unit/**` 50 个文件的 729+ 用例；协议层与镜像层的行/函数/分支覆盖 | 50 个测试文件里有大量纯函数黄金向量（CRC/帧/编解码/标定）与状态机时序用例，无法用界面或探针低成本复现 | 回归（历史修复点被改坏）、边界条件（补位零、写合并尾沿、超时冷却）、覆盖率跌破阈值 |
| **L3 虚拟下位机** | `selftest.mjs` 20 例（协议栈 / DFU 栈 / 故障注入 / 电平 / 诊断 / 冷启动）+ 虚拟桥接下的真实界面联调 | 唯一能**可控注入故障**（丢帧、延迟、CRC 错、断电、粘帧）又能让真实界面参与的环境；真机不可能按需制造这些 | 时序类缺陷（P6/P8）、故障恢复路径、以及"界面 ↔ 设备"契约在无硬件时无法回归 |
| **L4 真实界面 CDP** | 真实渲染进程的 DOM/交互/截图/双语；设备抽屉与诊断读数；真机链路的状态机表现 | 单测用 happy-dom 没有真实布局、Canvas、WebHID、Web Audio；探针（L5）绕过了 AppStore，无法证明"用户看到的行为" | 版式溢出、Canvas 曲线不可拖、语言缺键、抽屉 destroy 泄漏、诊断卡文案、错误提示可读性 |
| **L5 裸 HID 探针** | 设备侧真值：信息区 / 配置区 / 预设区 118 项原始字；`0x13` 连续读；`0x10` 写与回读 | 唯一能证明"设备里到底存了什么"，且**不依赖 Electron**（本机受限 shell 里 Electron 多进程 IPC 可能起不来，`tools/dfu/hidwin.py:1-7` 就是为此写的） | 上位机自说自话（界面显示对但设备没收到）、参数还原 0 失配无法证明、固件版本/型号无法独立核对 |
| **L6 打包冒烟** | `electron-builder --win portable` 产物 + 构建产物与打包产物各一次启动 | 只有它覆盖 asar 打包、`portable` 解包器、`app.isPackaged` 分支、`app.getVersion()` 真实版本、启动日志路径 | 交付物层面 P0（装了跑不起来、版本号错、白屏）——这是用户实际会双击的东西 |

### 1.3 层间能力边界（写进报告，避免过度声称）

1. **L4 不能替代 L5**：CDP 只能读 DOM。`AppStore` / `DeviceLink` **没有挂到 `window`**（`src/renderer/src/main.ts:99-106` 只暴露了 `window.__micstudioGo`），所以"界面显示 X"不等于"设备里是 X"。
2. **L5 不能替代 L4**：裸 HID 探针绕过 `AppStore` / `ParamSession`，证明不了写合并、超时重试、轮询开关这些主机侧语义。
3. **L3 不能替代 L5**：`tools/vdevice` 是 JS 实现的协议栈，真机固件的缺陷（例如只读不校验、补位零不丢弃）它按**正确**行为实现，因此不会复现。
4. **L1/L2 不能替代 L6**：`out/` 能跑不代表 `portable.exe` 能跑（`app.isPackaged` 分支、asar、解包器都只在 L6 出现）。
5. **DFU 层**：本轮 `device/dfu/**` 只有 L2 覆盖（S5），**L4/L5/L6 都不碰刷写**（Q6）。

### 3.3 退出码口径

1. **一律显式取 `$LASTEXITCODE`**，不要按"有没有红字"判断（需求文档 §7；`vite` 会往 stderr 打 CJS 弃用警告）。
2. 标准写法（PowerShell，可直接复制）：

```powershell
$out = & $node $pnpm --config.verify-deps-before-run=false run typecheck 2>&1
$code = $LASTEXITCODE
Write-Utf8NoBom (Join-Path $gates 'G1-typecheck-run1.log') (($out | Out-String) + "`nEXIT=$code`n")
if ($code -ne 0) { throw "G1 失败 exit=$code" }
```

3. **禁止**在判断前把输出塞进 `| Tee-Object`（`$LASTEXITCODE` 取自管道最后一条命令，容易误判）；也禁止用 `$?`。
4. 探针/脚本内部用 `process.exitCode`（不 `process.exit()`，避免截断 stdout）——`tools/vdevice/selftest.mjs` 已是这个写法（`selftest.mjs:2438-2442`）。
5. `pnpm` 前置守卫：本仓库依赖状态检查会在 `pnpm run` 前重跑 install（坑 2）。Stage 1 统一加 `--config.verify-deps-before-run=false`（阶段一 G1 合记录的就是这条，见 `gates/G1-exitcodes.txt`）。
6. 退出码汇总：每个 Stage 结束写 `exitcodes.txt`（一行一条 `项 exit=N`），Stage 7 汇总为 `summary/exitcodes-all.txt`。

### 3.4 快照 vs 工作树的判定口径（S9）

| 问题 | 口径 |
|---|---|
| 谁是正式判定对象 | **快照**（`$snap`，含 S4 的 fix 叠加，标记 `baseline+fix-N`） |
| 工作树结果算什么 | **差异附录**（`summary/final-run-*.log`），不进正式结论 |
| 快照无 `.git` 怎么判"有没有被改" | ①`Get-FileHash` 对目标文件与 `hashes-before.sha256` 比对；②整树比对用 `hashes-after-fix.sha256`（修复后）与 `hashes-before.sha256`（原始）两套并列；③禁止在快照里 `git` 操作（无 `.git`，会误在仓库生效） |
| 工作树比快照**差** | 缺陷清单单列「最终树回归」，本轮结论仍按快照，但报告必须写明"交付树存在回归" |
| 工作树比快照**好**（另一会话修了） | 记「已被外部修复（未经本会话复测）」；不得据此把快照的 fail 改 pass |
| 依赖漂移（S1） | 每次跑门禁前比对 `package.json` / `pnpm-lock.yaml` / `third_party/web_hid_utils` HEAD 与 `hashes-before.sha256`；不一致 → 记「依赖漂移」并注明影响面 |
| `node_modules` 写保护 | 测试期间禁止任何对 `node_modules` 的写操作（联接会穿透到仓库，S1）；`vitest --coverage` 输出默认落 `<cwd>/coverage`（`vitest.config.ts` 未配 `reportsDirectory`），在快照内安全 |

### 3.5 修复落点与 fix-diff 流程（S4）

```
① 复现 → ② 定级（P0–P3）→ ③ 记录 diff → ④ 同步快照 → ⑤ 快照上复测 → ⑥ 更新清单
```

1. **只改工作树**（`$root`）。改前先比对目标文件 SHA256 与 `hashes-before.sha256`：一致才改；不一致（另一会话动过）→ **不改**，把冲突写进缺陷清单并请用户裁决。
2. 记录 `& $git -C $root diff -- <files>` 到 `fixes/<ID>.diff`（`$git = 'C:\Program Files\Git\cmd\git.exe'`）。
3. 同步覆盖到快照对应路径（`Copy-Item -Force`），并追加一行到 `fixes/fixes-index.md`；快照状态标记 `baseline+fix-<ID>`。
4. 在快照上重跑**受影响门禁 + 相关测试项**（例如改了 `device/proto/session.ts` → 重跑 G1/G2/G3 + P6 + V 相关项），证据用 `-rerun` 后缀。
5. 重新生成 `hashes-after-fix.sha256`（只列改动文件 + 其所在目录即可，但必须在文件头注明生成时间与 fix 列表）。
6. **不 commit、不 stash、不 checkout**（S14）。DR 只在用户要求时做。

## 4. CDP 驱动方案

### 4.1 为什么用 CDP 而不是桌面截图

坑 9：非交互会话下 `Graphics.CopyFromScreen` 长时间不返回。Electron 自带两条可靠通道：
- **一次成像**：主进程参数 `--screenshot=<abs path>` → `win.webContents.capturePage()` → `toPNG()`（`src/main/screenshot.ts:19-49`，`src/main/index.ts:219-239`），出图后 `app.exit(0)`；
- **多时刻取证**：`--remote-debugging-port` + `Page.captureScreenshot`（可任意次数、可配合交互、可读 DOM）。

两者都拿**真实像素**（含 DPR 缩放），不依赖桌面合成器。`--screenshot` 只能截一张，所以 U 系列多步走查必须用 CDP。

### 4.2 启动参数（可直接复制）

```powershell
$electron = Join-Path $snap 'node_modules\electron\dist\electron.exe'
$ud = 'D:\Temp\micstudio-fulltest\userdata-ui-mock'
$port = 9411
Remove-Item Env:ELECTRON_RUN_AS_NODE -ErrorAction SilentlyContinue   # 坑 13
$env:MICSTUDIO_USER_DATA = $ud
$proc = Start-Process -FilePath $electron -PassThru -WorkingDirectory $snap -ArgumentList @(
  '.',
  '--no-sandbox',                                   # 坑 14/18：必须
  "--remote-debugging-port=$port",
  '--width=1280', '--height=820',                   # 内容区约 1266×783，U1 的判据视口
  '--disable-background-timer-throttling',
  '--disable-renderer-backgrounding',
  '--disable-backgrounding-occluded-windows',
  '--disable-features=CalculateNativeWinOcclusion'
)
```

- `cwd` 必须是**被测树**（`$snap` 或 `$root`），否则 `electron .` 读到的是另一份 `package.json`。
- `--width/--height` 由主进程读取（`src/main/index.ts:204-208` → 默认 1280×820，`src/main/window.ts:16-17`）。
- 后四个开关的作用：窗口被遮挡/最小化时 Chromium 会节流定时器，走查会假死（`verify-supplement-20261113.mjs:34-38` 已在用）。

## 5. 裸 HID 方案（ctypes）

### 5.1 为什么需要它

- 本机受限 shell 里 Electron 多进程 IPC 可能起不来（`tools/dfu/hidwin.py:1-7` 明确写了这一点），ctypes 直连 HID 不依赖 named pipe；
- 真机真值只能由它给出（界面显示 ≠ 设备内容）；
- `0x13` 连续读 + `0x10` 写是协议层最小操作集，逻辑简单、可复核。

### 5.2 读写路径（已有能力，不要重写）

| 能力 | 位置 | 说明 |
|---|---|---|
| 枚举 HID 接口 | `hidwin.enumerate_hid()`（`tools/dfu/hidwin.py:175`） | 返回 `{path, vid, pid, product, ...}`，`vid`/`pid` 是**十六进制字符串**（`real8-health.py:91-93` 用 `int(item['vid'],16)` 比较） |
| 打开 / 关闭 | `hidwin.HidDevice(path)` / `.close()`（`:220-247`） | `CreateFileW` + `FILE_FLAG_OVERLAPPED` |
| 写一条 OUT 报告 | `.write(bytes, timeout_ms=2000)`（`:248`） | 返回耗时（秒）；首字节是 **Report ID `0x51`** |
| 读一条 IN 报告 | `.read(timeout_ms=200)`（`:267`） | 超时返回 `None`；首字节是 Report ID（设备为 `0x11`） |
| 帧编解码 | `real8-health.py:32-69`（crc16 / encode / decode_stream） | Modbus CRC-16（poly `0xA001`，init `0xFFFF`，**低字节在前**） |
| DFU / 状态 / 版本 | `tools/dfu/m001-dfu.py` 子命令 `state` / `verify` / `package`（`:1-15`） | 本轮只用 `state`/`verify`/`package`，**禁用 `enter`/`flash`/`flash-all`**（Q6） |

一帧的字节布局（与 `device/proto/frame.ts` 一致，`real6-registers.js:17-29` 同款实现）：

```
[0] UnitID(0x00) [1] Func [2] LenHi [3] LenLo [4..] Data [len-2] CRCLo [len-1] CRCHi     Len = len(Data)+6
读（0x13）：Data = StartHi StartLo CountHi CountLo              应答 Data = StartHi StartLo CountHi CountLo + Words…
写（0x10）：Data = AddrHi AddrLo ValueHi ValueLo（可多组）      应答 = ACK 帧（Func 0x10）
```

分片：每片 **63 B payload**，前加 Report ID `0x51` 组成 64 B OUT 报告；帧短时尾部补 `0x00`；两片之间 `sleep(0.002)`（`real8-health.py:105-108`）。入站按"读到 `0x11` 就剥掉首字节"再交给 `decode_stream`（`:116`）——它已经会跳过 `00 00` 补位并校验 CRC。

### 5.3 46 项参数的地址 / 原始值如何反算

1. **地址来源**：`domain/params.ts` 的 46 个 `id` 各带 `addr`；寄存器规格（范围/步进/单位/权限/默认**原始值**/标定）在 `device/registers.ts` 的 `REGISTERS`（`registers.ts:356-360`），用 `findRegister(addr)` 取。
2. **原始值 → 工程量**：`fromRaw(spec, raw)`（`registers.ts:475-479`）内部按 `spec.scale`（`raw` / `linear{mul,add}`）换算；`defaultOf(spec)` = `fromRaw(spec, spec.defaultRaw)` 再夹紧（`:482-485`）。
3. **工程量 → 原始值**（写入用）：`toRaw(spec, value)`（`:469-472`）= 先 `snap()` 量化到步进、再换算、再夹到 `[rawMin, rawMax]`。
4. **界面显示值 → 比对**：界面文本用 `domain/values.ts` 的 `formatValue({...spec, default: defaultOf(spec)}, fromRaw(spec, raw))`；`real6-compare.mjs:56-71` 就是这条链路。
5. **EQ 7 段**：`eqBandAddr(band, field)`（`registers.ts:405-411`），基址 `0x2027`、步长 5、字段序 `enable,type,freq,gain,q`。
6. **三分频三区**：`drc3Addr(section, field)`（`:431-438`），`low`=`0x2063`、`high`=`0x2068`、`mid`=`0x206D`。
7. **预设区全量 118 项**：`0x2000`–`0x2075`；其中 `0x2000` 是校验和、`0x2001` 是有效标志（`registers.ts:55-56`），还原时**不要**写这两项。
8. **字符串字段**（型号/名称/SN/固件）：`DEV_INFO`（`registers.ts:369-377`）给首址与词数；解码用 `decodeAsciiWords()`（`:488-500`，高字节在前、遇 `0x00`/`0xFF` 停）。

> ⚠️ 现有 `real6-compare.mjs:33-49` 的 `SEEDS` 只有 **42 项**（V0.3 前的口径）。本轮 P1/R4 要求 **46/46**，该文件属于"需修"（补 4 项：`0x2072`–`0x2075` 中的可操作项，并按 R4 给只读项单独说明），不得直接把它当 P1 证据。

### 5.5 并发铁律

- **同一时刻只能有一个进程打开真机 HID**：应用开着真机通道时跑裸 HID 探针会打不开或抢走报文。顺序：先关应用（或让它断开）→ 跑裸 HID → 再开应用。

| 文本截断 | `text-overflow: ellipsis` 或 `white-space: nowrap` 且 `scrollWidth > clientWidth + 1` | P2 |
| 输入框裁切 | `input` 的 `scrollWidth > clientWidth + 1`（数字/单位放不下） | P2 |
| 横向越界 | 元素 `rect.left < -1` 或 `rect.right > innerWidth + 1`，且父容器不可横向滚动 | P2 |
| 纵向溢出 | `.console` 在 `overflow-y: visible` 下 `scrollHeight > clientHeight + 2` | P2 |
| 抽屉横向滚动 | `.modal-body` 在 `overflow-x: visible` 下 `scrollWidth > clientWidth + 2` | P2 |
| 元素重叠 | 同父容器两个可见候选元素（卡片/参数行/开关/按钮/段表/抽屉行）交叠 > 4×4 px，且无包含关系 | P2 |
| 多 active | 同一场景条/音色条/分段控件/导航出现 >1 个 `.is-active` | P1 |
| 状态冲突 | `tone=error` 但 sync=ready；场景高亮与音色不一致；EQ 旁通开但输入仍可用；ENC 关但档位仍可点 | P2（已知 O-02 记 P3） |
| 缺键/混杂 | 出现 `console.*`/`param.*` 等 key 原文；EN 界面出现中文字符 | P1 |
| 低对比度 | 文本色与背景色亮度比 < 2.2（近似；只提示） | P3 |

### 12.3 视图矩阵

主界面（console）＋高级参数 5 个分区（input / dynamics / eq / drc / lighting）＋设备抽屉＋设置抽屉＋固件抽屉 = **9 屏**；× 中/英 × 3 档视口 = **54 屏截图**；另加虚拟桥死端口的**错误态** 1 屏。每屏：先 `scrollIntoView`，再执行 `window.__audit.scan()`，最后 `Page.captureScreenshot`。

- `ui-audit.json`：逐屏 `issues[]`（type / target / text / 尺寸）＋ metrics（视口、节点数、modal 高度、console 高度）。
