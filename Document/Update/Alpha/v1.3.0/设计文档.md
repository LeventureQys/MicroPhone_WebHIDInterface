## 1. 背景与目标

### 1.1 要解决的问题

现有上位机 **MIC STUDIO**（Electron + WebHID）已经能通过 Modbus 风格参数协议调节 M001 麦克风的 46 项标量参数与 7 段 EQ（真值表：`src/renderer/src/device/registers.ts`，派生：`src/renderer/src/domain/params.ts`）。但调参门槛高：用户得先理解"噪声门阈值 −41 dB""压缩比 3.0"这类概念，才能得到"我想要的声音"。

本版要交付的是：**用户喊「小唐小唐」，用一句中文描述听感（"声音有点闷""齿音太重"），系统在 2.5 秒内把麦克风参数改成对应的值，并用一句短话回报**。全部推理跑在本机 CPU，全程离线。

### 1.2 本版范围（由 Q1=A 定案）

**做**：
1. 独立的语音侧车（Python）跑通 `采集 → 唤醒 → 端点 → ASR → 意图 → 结构化命令`；
2. 独立的执行器（Node/TS）把结构化命令变成参数写入，落到 **dry-run** 与 **虚拟下位机** 两个靶上，并做回读校验与撤销；
3. **知识本体**（`kb.ts`）：把"用户会怎么说 → 该动哪些参数"写成可执行的单一真值，并生成规则表 / 词表 / 训练标签 / 评测期望四份产物；
4. **蒸馏数据与微调**：以知识本体为教师标签、本机 Qwen3-8B 改写表述，合成 5 000 条语料，QLoRA 微调 Qwen3-1.7B 学生模型；
5. 三层评测（文本级 / 音频级 / 真人抽检）与重跑脚本，含 base / few-shot / 微调 三档对照。

**不做**（明确排除，不算缺陷）：
| 排除项 | 原因 |
|---|---|
| 修改 `src/**` 任何文件 | Q1=A：本版不融入产品；M9 才接应用内面板 |
| 真机（M001）闭环 | 同上；真机在 M5 用既有探针**抽检**，不作门禁 |
| 应用内 UI / IPC 命令通道 | 推到 M9 |
| 固件升级、预设存取删、出厂复位、通讯参数、只读参数的语音控制 | Q5=A 的 `excluded` 层 |
| 方言、英文指令、多语言播报 | D13 |
| **推理**用 GPU | Q3=A / D14；训练用 GPU 是允许的（见 §4.1 的 SubStage 5.2） |
| 云端模型 / 外部 API | 离线交付；教师模型也在本机跑 |

### 1.3 术语

| 术语 | 含义 |
|---|---|
| **L1 / VoicePlan** | 意图层的输出：模型或规则解析器产出的"要做哪些语义动作" |
| **L2 / VoiceCommand** | 执行层的输出：宿主可直接消费的 `writes` / `bandWrites` / `scene` / `tone` |
| **target** | 语义目标（12 项），如 `brightness`、`muddiness`。**模型只说目标，不说 dB**（Q2=A） |
| **strength** | 幅度档位 `slight / medium / strong`，由规则表乘以系数 |
| **tier** | 执行分层：`immediate`（立即）/ `confirm`（二次确认）/ `excluded`（拒绝） |
| **turn** | 一次完整的"唤醒→指令→落地"，有唯一 id（`t-0001` 递增） |
| **sink** | 落地靶：`dry`（只算不写）/ `vdevice`（虚拟下位机）/ 预留 `device`（真机，M9） |
| **sidecar** | Python 语音侧车；**executor** 指 Node 执行器 |
| **知识本体 / kb** | `tools/voice/contract/kb.ts`：维度、场景、说法、规则数值的**唯一真值**。四份产物（运行时规则表、规则词表、训练标签、评测期望）都由它生成 |
| **教师模型** | Qwen3-8B（Q4_K_M，本机 CPU/GPU 均可跑）。**只改写表述**，不产出标签 |
| **学生模型** | 微调后的 Qwen3-1.7B（LoRA 合并 → Q4_K_M）。推理仍是学生模型 |
| **蒸馏** | 本设计里的含义：知识本体产标签 + 教师改写表述 → 合成语料 → 微调学生模型（不是 logits 蒸馏） |

### 1.4 成功判据（一句话，验收按这个拆）

> 对着麦克风说「小唐小唐，声音有点闷」，2.5 秒内虚拟下位机的 250 Hz/1 kHz 段增益按规则表下降、4 kHz 以上不变或微升，助手回一句中文；说「撤销」能回到执行前的值；说「放首歌」不写任何参数并回固定话术。

| 关注点 | 唯一拥有者 | 别人怎么拿到 |

### 2.4 硬约束

| 约束 | 值 | 违反的后果 |
|---|---|---|
| 离线 | 运行时零联网 | 演示环境断网直接不可用 |
| 推理设备 | CPU only，`llama-server -t 14` | 延迟不达标 / 违背需求 |
| 延迟 | 停口→落地 ≤ 2.5 s；唤醒→应答音 ≤ 300 ms | 体验崩 |
| LLM 输出 | ≤ 96 token（`say` ≤ 30 字；典型 50–70 token） | 截断会破坏 schema 合法性；过大则单轮 > 3 s（实测 tok/s 反推） |
| 现状代码 | `src/**` 零改动；`pnpm run typecheck/test/build` 全绿 | 违反 Q1=A / D17 |
| 模型体积 | `models/` 不入库，`fetch-models.mjs` 必须能一键重建 | 仓库被 1.8 GB 二进制污染 |
| **数值只由上位机算** | 模型与 ASR 都不产出 dB/Hz/档位；`set` 的数值必须能在用户原话里找到（数字接地，§3.5） | 模型编数值 → 用户听到的不是他要的，且无法验收 |
| **一切改动都写进设备** | 任何参数变化都必须经 `Transport`/sink 写下去（本版是 vdevice），不允许"只改界面本地值" | 与真机行为不一致，验收时无法用回读取证 |
| 训练环境隔离 | 训练依赖（torch/Unsloth）装在 `tools/voice/.venv-train`，**不污染** `.venv` | 推理侧被打包进 3 GB 依赖 |

## 3. 契约（实现以本节为准）

### 3.1 语义目标词表 `Target`

`tools/voice/contract/targets.ts` 是唯一真值，导出以下常量；`emit.mjs` 把它写成 `schema/targets.json`（Python 消费）。

```ts
// 可调（tune）：用户在描述"听感"——13 个维度，全部由 kb.ts 定义
export type TuneTarget =
  | 'brightness'   // 明亮度：高频多寡
  | 'warmth'       // 温暖度：中低频厚度（"单薄"是它的 less 侧）
  | 'lowEnd'       // 低频量感：63–250 Hz
  | 'muddiness'    // 浑浊/闷：250–1000 Hz 堆积
  | 'clarity'      // 清晰度/人声突出：1k–4k presence
  | 'sibilance'    // 齿音/嘶：6k–12.5k
  | 'harshness'    // 毛刺/刺耳：2k–5k（与 sibilance 分主次频段）
  | 'noiseFloor'   // 底噪/环境噪声
  | 'compression'  // 压缩强度（忽大忽小）
  | 'loudness'     // 响度（声音小/大）
  | 'gate'         // 噪声门（气口、呼吸声、断续）
  | 'limiter'      // 防爆音强度
  | 'rgbMode';     // 灯效模式

// 可开关（toggle）：上面的子集 + 两个"会切断链路"的目标
export type ToggleTarget =
  | 'noiseFloor' | 'gate' | 'limiter' | 'compression' | 'rgbMode'
  | 'mute'      // mic.mute（0x2022）—— confirm 层
  | 'monitor';  // hp.OnOff（0x2059）—— confirm 层
```

**只识别、不执行**（`kb.ts` 里单列 `explainOnly`，命中时回 `unsupported` + 一句解释，**不写任何参数**）：`echo`（回音/房间空间感）、`plosive-pops`（喷麦声，靠离麦距离与防喷罩）、`background-music`（背景音乐串音）、`hum`（50 Hz 电流声，硬件接地问题）。把它们写成"识别得出、但不许乱调参数"，正是为了避免模型把"有回音"映射成"加 EQ"。

#### 3.1.1 频段寻址（`eq` 动作）

用户经常直接点名频段，必须支持（这是"小模型要调的东西很多，比如 EQ"的主要落点）：

```jsonc
{"kind":"eq","band":4,"direction":"less","strength":"medium"}            // "250 赫兹压一点"
{"kind":"eq","centerHz":3000,"direction":"less","strength":"slight"}     // "三 k 太尖"
{"kind":"eq","band":6,"field":"q","direction":"more"}                    // "这一段的 Q 太窄"
```

- `band`（1..7）与 `centerHz` 二选一；`centerHz` 由 `kb.ts` 的频段映射表**就近取整**到 band（63/250/1k/4k/12.5 kHz；落在 band1/band2 的 HPF/LPF 上 → 返回 `unsupported` 并提示"这是滤波器不是均衡段"）；
- `field` 默认 `gain`，只有用户说到"Q/带宽/宽度"时才用 `q`，说到"频点/频率"时才用 `freq`；
- `direction` / `strength` 语义与 `tune` 相同，数值由 kb 的 `EQ_DELTAS` 表给出（见 §3.4）。


**direction 语义（重要，别按直觉猜）**：`more` / `less` 描述**用户感知属性的强弱**，不是参数值的方向。

| target | `more` 表示 | `less` 表示 | 落到哪 |
|---|---|---|---|
| `brightness` | 更亮 | 更暗/更闷 | EQ band6/band7 增益 |
| `warmth` | 更暖更厚 | 更冷更薄 | EQ band3/band7 增益 |
| `lowEnd` | 低频更多 | 低频更少 | EQ band3/band4 增益 |
| `muddiness` | 更闷 | 更通透 | EQ band4/band5 增益（`less` 时下削） |
| `clarity` | 更清晰 | 更糊 | EQ band5/band6 增益 |
| `sibilance` | 齿音更重 | 齿音更轻 | EQ band7/band6 增益 |
| `harshness` | 更毛刺刺痛 | 更圆润 | EQ band6/band5 增益 |
| `noiseFloor` | **降噪减弱**（底噪更明显） | **降噪加强** | `enc.Level`（0..3）与 `enc.OnOff` |
| `compression` | 压缩更强（更平稳） | 压缩更弱 | `comp.Threshold`、`comp.Rate` |
| `loudness` | 更响 | 更轻 | `comp.MakeUpGain`（0..60 dB） |
| `gate` | 门更严（弱声切得更狠） | 门更松 | `noisegate.threshold_db` |
| `limiter` | 保护更强 | 保护更弱 | `limit.Threshold` |
| `rgbMode` | 模式 +1（循环 0..7） | 模式 −1（循环） | `rgb.Mode` |

**中文别名表**（`lexicons/zh.json` 的 `aliases`，规则解析器用；完整 60+ 条在 SubStage 3.2 给出，这里是必须覆盖的语义种子）：

| target | 别名（至少这些） |
|---|---|
| `brightness` | 亮、明亮、通透、清亮、发亮、亮一点、暗、更暗、闷（`less` 侧） |
| `warmth` | 暖、温暖、厚、厚实、圆润、冷、薄、干 |
| `lowEnd` | 低音、低频、重低音、下潜、轰、发轰 |
| `muddiness` | 闷、浑、浑浊、糊、箱音、鼻音 |
| `clarity` | 清楚、清晰、人声突出、靠前、发虚 |
| `sibilance` | 齿音、刺、尖、si 音、嘶 |
| `noiseFloor` | 底噪、噪音、噪声、电流声、呼呼声、环境声 |
| `compression` | 压缩、忽大忽小、声音不稳、太平 |
| `loudness` | 声音小、大声、音量、响度、听不清 |
| `gate` | 气口、呼吸声、杂音、断断续续、吞字 |
| `limiter` | 爆音、破音、削顶、喷麦、过载 |
| `rgbMode` | 灯效、灯、颜色、氛围灯 |
| `harshness` | 毛刺、刺耳、扎耳朵、刮、硬、尖锐（2–5 kHz 侧） |

**场景词表（8 种 → 内置 5 场景 + 参数补丁，由 `kb.ts` 的 `SCENARIO_MAP` 定义）**：

| 用户说法 | 映射 |
|---|---|
| 直播 / 带货 / 开黑（含直播） | `podcast` + `enc.Level+1` + 门限 +3 dB |
| 会议 / 网课 / 上课 | `podcast`（不额外压噪，避免切字） |

### 3.2 L1 `VoicePlan`（意图层输出）

字段表：

| 字段 | 类型 | 必填 | 约束 | 说明 |
|---|---|---|---|---|
| `v` | `1` | 是 | 常量 | 契约版本 |
| `status` | `'ok' \| 'clarify' \| 'unsupported'` | 是 | 枚举 | 见下 |
| `ops` | `VoiceOp[]` | `status==='ok'` 时非空（1..4 项） | 联合类型 | 要做的事 |
| `question` | `string` | `status==='clarify'` 时必填 | ≤ 20 字 | 追问话术 |
| `say` | `string` | 是 | ≤ 30 字 | 直接播报的中文 |
| `confidence` | `0 \| 0.25 \| 0.5 \| 0.75 \| 1` | 是 | 离散值（GBNF 友好） | < 0.5 时上层必须降级为 `clarify` |

`VoiceOp` 联合（`kind` 判别）：

```jsonc
{"kind": "tune",   "target": "<TuneTarget>",  "direction": "more|less", "strength": "slight|medium|strong"}
{"kind": "eq",     "band": 1..7,  "direction": "more|less", "strength": "…", "field": "gain|q|freq"}
{"kind": "eq",     "centerHz": 3000, "direction": "more|less", "strength": "…", "field": "gain|q|freq"}
{"kind": "toggle", "target": "<ToggleTarget>", "on": true}
{"kind": "set",    "param": "<ParamId>",       "value": 4.5}
{"kind": "scene",  "scene": "quiet|game|podcast|sing|custom"}
{"kind": "tone",   "tone": "flat|vocal|warm|bright|custom"}
{"kind": "undo"}
```

**数字接地（本版新增的硬规则）**：`set` 的 `value` 必须能在**用户原话**里找到对应的数字（允许中文数字、小数、负号，由 `normalize.py` 已转成阿拉伯数字）。找不到 → 该 op 直接丢弃并记 `danger:{reason:'ungrounded-number'}`。理由：需求方明确"小模型调整不了 dB 数"，这条把"模型不许编数值"从设计意图变成代码强制；`tune`/`eq` 不带数值，天然不受影响。

`ParamId` = **44 个可写标量**（`domain/params.ts` 的 46 项里扣除 2 项只读 `gain.Mic` / `gain.Hp`，如 `enc.Level`、`comp.Threshold`、`noisegate.threshold_db`）+ 28 个 EQ 字段 id（`eq.band1.type` … `eq.band7.q`），**共 72 个**。全表由 `targets.ts` 从 `PARAMS.filter(p => !p.readonly)` 与 `eqBandAddr` 派生，不手抄。（v2.1 更正：v2 写的 74 把两项只读参数算了进去，与 §3.3 的 `excluded` 表及问题清单 D7 冲突。）

**四个必须实现的行为样例**（评测集直接引用）：

```jsonc
// 1) 自由描述 → 语义动作（**规则层**命中时的形态：确定性解析，confidence 恒 1、"有点"归 slight）
{"v":1,"status":"ok","say":"把闷的地方收一收","confidence":1,
 "ops":[{"kind":"tune","target":"muddiness","direction":"less","strength":"slight"}]}
//    同一句走 **LLM 层**时可能是 medium / confidence 0.75——两层的 strength 判定本就不必一致，
//    评测按 (target, direction) 记 F1、strength 另计 strengthAcc（见 SubStage 5.3 §4.1）。

// 2) 显式数值 → set
{"v":1,"status":"ok","say":"第六段提 3 分贝","confidence":1,
 "ops":[{"kind":"set","param":"eq.band6.gain","value":3}]}

// 3) 与调参无关 → 拒绝（不是错误码）
{"v":1,"status":"unsupported","say":"我只管调麦克风音色，比如“声音亮一点”","confidence":1,"ops":[]}

// 4) 相关但没听清 → 一次追问
{"v":1,"status":"clarify","question":"想调哪一块？比如声音太闷、齿音太重","say":"","confidence":0.25,"ops":[]}
```

**生成方式**：`schema/voice-plan.schema.json` 由 `contract/schemas.ts` 构造、`emit.mjs` 写出；LLM 请求里以 `response_format:{"type":"json_schema","json_schema":{...}}` 传入（llama.cpp 支持；**注意 schema 不会进提示词**，所以 `prompts/system.zh.txt` 必须用自然语言把结构再讲一遍——见 llama.cpp grammars/README 的已知限制）。

|---|---|---|
| `v` | `1` | 版本 |
| `turn` | `string` | `t-0001` 递增，进程内唯一 |
| `status` | `'applied' \| 'needs_confirm' \| 'rejected' \| 'dry-run'` | 由 tier 与 sink 决定 |
| `writes` | `{param: string, value: number}[]` | 46 项标量写入（工程量，已夹紧） |

**分层规则（原子性）**：一次 turn 里只要有一个写入落在 `confirm` 层，则**整轮都不写**，返回 `status:'needs_confirm'` + `preview` + `confirmToken`；用户下一句说「确认/好/可以/行」才带着同一个 token 重新提交。`excluded` 的写入直接丢弃并记进 `danger`，若全部被丢弃则 `status:'rejected'`。

`tier` 判定表（逐参数，完整）：

| tier | 参数 |
|---|---|
| `immediate` | `enc.Level`、`enc.OnOff`、`eq.mode`、`comp.*`（7 项）、`limit.Enable`、`limit.Threshold`、`limit.Attack`、`limit.Release`、`noisegate.*`（7 项）、`drc3.*`（18 项）、`rgb.OnOff`、`rgb.Mode`、全部 EQ 段字段、`scene`、`tone` |
| `confirm` | `mic.mute`(0x2022)、`mic.sigMute`(0x2058)、`hp.OnOff`(0x2059) |
| `excluded` | `gain.Mic`(0x2023)、`gain.Hp`(0x205A)、`micLevel`(0x2057)（只读）；出厂复位(0x100A)、进 DFU(0x1008)、通讯参数(0x1001)、预设存取删(0x1004–0x1006)、预设名(0x2002–0x2021)、`validFlag`(0x2001)、`checksum`(0x2000) |

> 与问题清单 Q5 原文的差异：Q5 把 `drc3.Enable` 列在二级，本文件下调到 `immediate`。判定标准写死为"**是否切断助手自己的耳朵或用户的听觉反馈**"——`drc3.Enable`/`comp.Enable`/`limit.Enable`/`noisegate.Enable` 只改音质，不切断输入，所以 `immediate`；`mic.mute`/`mic.sigMute`/`hp.OnOff` 会切断或改变反馈，所以 `confirm`。若产品要求改回，只改 `canonicalize.ts` 的一张表。

### 3.4 语义 → 参数 规则表（`contract/rules.ts`）

**这是本设计的核心**：dB 数值只在这里产生（物理位置是 `tools/voice/contract/kb.ts`，由 `emit.mjs` 导出到 `gen/rules.json` 供执行器读），模型与 ASR 都不产出数值。

结构：

```ts
export type RuleAction =
  | { kind: 'param'; id: string; delta: number }          // 相对当前值
  | { kind: 'band'; band: 1|2|3|4|5|6|7; field: EqField; delta: number }
  | { kind: 'paramSet'; id: string; value: number }        // 绝对（开关/档位）
  | { kind: 'bandSet'; band: 1|2|3|4|5|6|7; field: EqField; value: number };

export interface Rule {
  target: TuneTarget | 'mute' | 'monitor';
  more: Record<Strength, RuleAction[]>;
  less: Record<Strength, RuleAction[]>;
  toggleOn: RuleAction[];
  toggleOff: RuleAction[];
}
```

`Strength` 系数：`slight = 1`、`medium = 2`、`strong = 3`（下表数值已是"×系数之后"的成品，便于逐行核对）。

| target | `more`（slight / medium / strong） | `less`（slight / medium / strong） |
|---|---|---|
| `brightness` | band7.gain **+1.5 / +3 / +5**；band6.gain **+1 / +2 / +3** | band7.gain **−1.5 / −3 / −5**；band6.gain **−1 / −2 / −3** |
| `warmth` | band3.gain **+1.5 / +3 / +4.5**；band7.gain **−1 / −2 / −3** | band3.gain **−1.5 / −3 / −4.5**；band7.gain **+1 / +2 / +3** |
| `lowEnd` | band3.gain **+2 / +4 / +6** | band3.gain **−2 / −4 / −6** |
| `muddiness` | band4.gain **+1.5 / +3 / +4.5**；band7.gain **−1 / −2 / −3** | band4.gain **−1.5 / −3 / −4.5**；band7.gain **+1 / +2 / +3** |
| `clarity` | band5.gain **+1 / +2 / +3**；band6.gain **+1 / +1.5 / +2** | band5.gain **−1 / −2 / −3**；band6.gain **−1 / −1.5 / −2** |
| `sibilance` | band7.gain **+1.5 / +3 / +5**；band6.gain **+1 / +1.5 / +2** | band7.gain **−1.5 / −3 / −5**；band6.gain **−1 / −1.5 / −2** |
| `harshness` | band6.gain **+1.5 / +3 / +4.5**；band5.gain **+0.5 / +1 / +1.5** | band6.gain **−1.5 / −3 / −4.5**；band5.gain **−0.5 / −1 / −1.5** |
| `noiseFloor` | `enc.Level` **−1 / −2 / −3**（夹紧 0..3），到 0 时同时 `enc.OnOff=0` | `enc.Level` **+1 / +2 / +3**（夹紧 0..3），同时 `enc.OnOff=1` |
| `compression` | `comp.Threshold` **−3 / −6 / −10 dB**；`comp.Rate` **+1 / +2 / +3** | `comp.Threshold` **+3 / +6 / +10 dB**；`comp.Rate` **−1 / −2 / −3** |
| `loudness` | `comp.MakeUpGain` **+1.5 / +3 / +6 dB** | `comp.MakeUpGain` **−1.5 / −3 / −6 dB** |
| `gate` | `noisegate.threshold_db` **+3 / +6 / +9 dB**（更严） | 同值 **−3 / −6 / −9 dB**（更松），到 −91 时 `noisegate.Enable=0` |
| `limiter` | `limit.Threshold` **−1 / −2 / −3 dB**（更早限幅） | `limit.Threshold` **+1 / +2 / +3 dB** |
| `rgbMode` | `rgb.Mode` 循环 **+1 / +2 / +3**（0..7 取模） | 循环 **−1 / −2 / −3** |

开关（`toggle`）：

| target | `on` | `off` |
|---|---|---|
| `noiseFloor` | `enc.OnOff=1` | `enc.OnOff=0` |
| `gate` | `noisegate.Enable=1` | `noisegate.Enable=0` |
| `limiter` | `limit.Enable=1` | `limit.Enable=0` |
| `compression` | `comp.Enable=1` | `comp.Enable=0` |
| `rgbMode` | `rgb.OnOff=1` | `rgb.OnOff=0` |
| `mute` | `mic.mute=1` | `mic.mute=0` |
| `monitor` | `hp.OnOff=1` | `hp.OnOff=0` |

**EQ 频段寻址的增量表 `EQ_DELTAS`**（`eq` 动作用；作用在用户点名的那一段上）：

| `field` | `more`（slight / medium / strong） | `less`（slight / medium / strong） |
|---|---|---|
| `gain` | **+1 / +2 / +3 dB** | **−1 / −2 / −3 dB** |
| `q` | **+0.5 / +1 / +2**（夹紧 0.1..12） | **−0.5 / −1 / −2**（夹紧 0.1..12） |
| `freq` | **+10% / +20% / +30%**（相对当前值，夹紧 20..20000 Hz） | **−10% / −20% / −30%** |

`centerHz` → band 的就近映射：`63→band3`、`250→band4`、`1000→band5`、`4000→band6`、`12500→band7`；落在 `band1`（HPF 50 Hz）或 `band2`（LPF 20 kHz）上时返回 `unsupported`（提示"那是滤波器，不是均衡段"）。映射表写在 `kb.ts` 的 `BAND_CENTERS` 里，`emit.mjs` 一并导出。

**为什么用相对 delta**：`"再亮一点"` 是相对语义，累加才自然；且 delta 天然适合撤销（记住反向 delta 或前值快照）。

**单轮总量上限**（防止一句话把曲线打飞）：任一 EQ 段单轮累计 |Δgain| ≤ **6 dB**；`enc.Level` 单轮 ≤ 3；`comp.MakeUpGain` 单轮 ≤ 6 dB；超出按上限截断并在 `preview` 里注明 `clamped`。

**场景与音色**（`scene` / `tone` op）：
- `scene` → 用 `domain/scenes.ts` 的 `scenePatch()` 得到 `params` + 7 段 `gains`，**整包写入**（与界面点场景一致）；`scene='custom'` 时 `gains` 取执行器当前 7 段值（不覆盖）。
- `tone` → 用 `domain/quick-controls.ts` 的 `EQ_PRESETS` 得到 7 段 `gains`，只写 `bandN.gain`。

### 3.5 夹紧、量化与非法值处置

| 情况 | 处置 | 证据 |
|---|---|---|
| 目标值超出寄存器范围 | **夹紧到范围端点**，不报错，`preview` 标 `clamped` | `registers.ts` 的 `toRaw()` 已实现夹紧与步进量化 |
| 目标值不在步进上（如 `q=1.23`） | 按 `step` 量化（`toRaw`→`fromRaw` 往返） | `registers.ts:451` `snap()` |
| `param` 不在 72 个 id 内 | 丢弃该 op，`danger.push({reason:'excluded'})`；其余照常 | `targets.ts` 的白名单 |
| `value` 非有限数 | 丢弃该 op，`danger.push({reason:'excluded'})` | — |
| `status:'ok'` 但 `ops` 为空 | 视为 `clarify`（上层降级） | §3.2 |
| `confidence < 0.5` | 上层降级成 `clarify`，不写任何参数 | §3.2 |
| `set` 的 `value` 在用户原话里找不到 | 丢弃该 op，`danger:{reason:'ungrounded-number'}`；其余照常 | §3.2 数字接地 |
| 命中 `explainOnly` 维度（回音 / 喷麦 / 电流声 / 背景音乐） | 返回 `unsupported` + 一句解释，**不写参数** | §3.1 |
| `undo` 但栈为空 | `status:'rejected'`，播报"没有可以撤销的操作" | §3.6 |

**工程量 ↔ 原始值**：执行器写 sink 前必须 `fromRaw(spec, toRaw(spec, value))` 往返一次，确保本地值与设备读回值不会差一档（与 `AppStore` 的做法一致，见 `domain/state.ts:99` 的 `quantizeBandField`）。

### 3.6 撤销模型

- 每次 `applied` 前，对被修改的每个 `(param | band.field)` 记前值快照 → 推入撤销栈；栈深 **5**。
- `POST /undo` 弹出栈顶，把前值原样写回（走同一套夹紧），返回 `status:'applied'`、`undoTurn` 指向上一个。
- 场景/音色的撤销：整包还原被修改的参数与 7 段增益（快照里就是全量，不需要特殊逻辑）。
- 撤销本身**也**入栈？不入：撤销后把该快照丢弃，避免"撤销的撤销"产生环。连续两次 `undo` 会连续回退到更早的状态。
- 播报话术：`"已撤销"`；若撤销的是 `confirm` 层的写入（静音等），话术追加 `"麦克风已恢复"`。

### 3.7 执行分层与"失聪"保护

见 §3.3 的 tier 表。额外硬规则（`canonicalize.ts` 必须实现）：

1. **静音后会失聪**：写入 `mic.mute=1` 或 `mic.sigMute=1` 的那一轮，`say` 必须**由规则表覆盖**为：`"已静音，请用界面上的开关恢复"`（不采用模型给的 `say`，因为模型不知道后果）。
2. **播报期间不采集**：`pipeline.py` 在 TTS 播放期间丢弃音频帧（半双工），避免自问自答；播完清空 KWS 缓冲。
3. **连续静音保护**：本次会话已执行过 `mic.mute=1` 时，后续 turn 的 `say` 一律追加 `"（麦克风处于静音，我可能听不到你）"`。

### 3.8 进程间协议（executor HTTP API）

默认监听 `127.0.0.1:8767`。**本版端口分配（唯一权威，任何 SubStage 不得临时占用别的端口）**：

| 端口 | 归属 | 谁起 | 用途 |
|---|---|---|---|
| 8765 | `third_party/web_hid_utils` 虚拟桥 | `tools/vdevice/run.mjs` | WebHID 桥（本次不改） |
| 8766 | 虚拟下位机控制面 | `tools/vdevice/run.mjs` | `GET/POST /control/registers` |
| **8767** | **执行器** | `tools/voice/executor.mjs` | `/health /state /plan /apply /undo` |
| **8768** | **推理侧 llama-server** | `voice server --model base\|student` | SubStage 3.3 / 5.3 用（base 或学生模型） |

### 3.9.1 原生采样率兜底（v2.2 新增，2026-11-24）

实测：本机 WASAPI / WDM-KS 端点**一律拒绝 16 kHz**（PortAudio `-9997 Invalid sample rate`），只有 MME / DirectSound 接受。若演示机的默认输入是纯 WASAPI 端点（蓝牙耳机、USB-C 耳机），固定 16 kHz 会让 `open_stream()` 报 `unavailable` —— **麦克风其实存在**。

规则：

1. 先按 **16 kHz** 打开；失败且 `kind === 'unavailable'`、错误信息含 `Invalid sample rate` 时，按该设备的**原生采样率**（`default_samplerate`，实测 44100/48000）重试；
2. 采集到原生采样率的样本后，**在 `audio_io` 内部线性插值重采样到 16 kHz**，对上层保持"永远 16 kHz"的契约不变；
3. `AudioStream.rate` 仍报 `16000`，另加只读字段 `source_rate: int`（等于 16000 表示未重采样）与 `resampled: bool`；`--selftest` 与 `selftest-12.json` 必须打印实际走了哪条路；
4. 日志里记一行 `[audio] 16 kHz 被拒（-9997），改用 48 kHz 采集 + 重采样`；
5. **仍不允许换成别的设备**（只换采样率，不换设备）；
6. 验收新增一条：合成 440 Hz 正弦 → 走原生采样率 + 重采样 → 峰值频率偏差 ≤ 5%、RMS 偏差 ≤ 1 dB（线性插值够用，KWS/ASR 都不需要高保真）。

这条兜底是**例外而不是默认**：能 16 kHz 就用 16 kHz，重采样路径只在端点拒绝时启用。

| 方法 | 路径 | 请求体 | 成功响应 |
|---|---|---|---|
| `GET` | `/health` | — | `{"ok":true,"sink":"vdevice","turn":"t-0007","undoDepth":2}` |
| `POST` | `/plan` | `VoicePlan` | `{"ok":true,"command":VoiceCommand}`（**只算不写**，`status:'dry-run'`） |
| `POST` | `/apply` | `VoicePlan` + 可选 `{"confirmToken":"..."}` | `{"ok":true,"command":VoiceCommand,"readback":{...},"mismatch":[...]}` |
| `POST` | `/undo` | `{}` | `{"ok":true,"command":VoiceCommand}` |
| `GET` | `/state` | — | `{"ok":true,"params":{...},"bands":[...]}`（当前状态，给评测与调试） |

**失败响应统一形状**：`{"ok":false,"error":{"code":"<CODE>","message":"<中文>","detail":{...}}}`，HTTP 状态：请求体不合法 `400`、被拒绝 `409`、sink 故障 `502`、内部错误 `500`。

错误码：

| 码 | 触发 | message 示例 |
|---|---|---|
| `E_PLAN_INVALID` | 缺字段/枚举非法/`ops` 超 4 项 | `意图结构不合法：缺少 status` |
| `E_ALL_EXCLUDED` | 所有写入都落在 `excluded` | `这些参数不支持语音调整` |
| `E_CONFIRM_EXPIRED` | token 超过 30 s 或与 plan 不匹配 | `确认超时，请再说一次` |
| `E_UNDO_EMPTY` | 撤销栈为空 | `没有可以撤销的操作` |
| `E_SINK_UNAVAILABLE` | vdevice 控制面连不上 | `落地靶不可用（虚拟下位机没起）` |
| `E_READBACK_MISMATCH` | 写入后回读与期望不一致 | `设备回读与写入不一致：0x205b` |

### 3.9 失败行为约定（每个环节，避免"抛异常还是返错误码"的猜测）

| 环节 | 失败形态 | 调用方处置 |
|---|---|---|
| 采集打开失败 | `audio_io.open_stream()` 抛 `AudioUnavailable(kind)`（`kind ∈ denied/unavailable/busy`） | 侧车打印中文原因并以退出码 3 退出；不静默降级到**别的设备**（但允许按 §3.9.1 降级到**原生采样率**） |
| VAD 200 ms 内判定异常 | 不抛，按"还在说话"处理 | 靠 6 s 上限兜底 |
| KWS 模型加载失败 | 抛 `RuntimeError`（带模型路径） | 退出码 4 |
| ASR 解码返回空文本 | 返回 `''`，不抛 | 继续（多半是噪声），播报"没听清"并退出本轮 |
| LLM 服务不可达 | `llm.py` 抛 `LlmUnavailable` | 侧车降级：只用规则层，`say` 追加"（模型没起来）"；**不重试** |
| LLM 输出无法解析 | `llm.py` 返回 `None`，不抛 | 侧车降级为 `clarify` |
| HTTP 400/409 | 侧车读 `error.code`，按 §3.8 的 message 播报 | 不重试 |
| HTTP 5xx / 连接失败 | 侧车重试 **1** 次（间隔 300 ms），仍失败则播报"底层没起来" | 不吞异常 |
| sink 写入后回读不一致 | 执行器返回 `E_READBACK_MISMATCH`，并**回滚**该 turn 已写的项 | 侧车播报"写入没生效" |

每轮一行 JSON，字段固定为：

{"turn":"t-0007","ts":"2026-11-24T10:31:02.117+08:00","wake_ms":120,

### 3.10.1 实施回填（2026-11-24，SubStage 4.3 交付后）

| 项 | 定案 |
|---|---|
| **日志键数** | **18 个键** = 上一行示例的 17 个 + `total_ms`（墙钟总耗时）。本文 §3.10 的写法、验收 F6 的"16 键"一律以 **18** 为准；执行器侧 `exec/exec-*.jsonl` 是另一份（17 键，不含 `total_ms`），两者不混 |

| **`--text` 模式的计时** | `audio_ms`、`wake_ms`、`asr_ms` **都为 `null`**（没跑这几段），`total_ms` 仍是墙钟 |

| **`plan` 顶层多带 `text`** | 允许：`canonicalize.ts` 只校验五键必需项、附加顶层键放行；`text` 参与数字接地与执行器日志。`digest()` 两端一致，不影响二次确认 |
| **TTS 环境限制** | 本机 Python 子进程是 Low 完整性级别，SAPI `Speak()` 抛"没有当前安全设置可用的语音"（与 2.1 的 `SelectVoice` 同源）。实测每次尝试 ~430–470 ms 后置 `tts_disabled`、之后不再起进程。**验收 F3 的"播报"只能作环境限制记录**；`tts_ms` 恒 0 不影响业务正确性 |

## 5. 关键设计决策（可追溯）

| 编号 | 决策 | 理由 | 替代方案与被否原因 |
|---|---|---|---|
| R-1 | 三进程：Python 侧车 / Node 执行器 / sink | ASR 生态在 Python，参数真值在 TS | 全 Python（要复制寄存器表，D2 禁止）；全 Node（ASR 无可用绑定） |
| R-2 | 模型不产出数值，规则表产出 | 实测 1.7B 会把 4.5 dB 写成 45；dB 合理性属工程常识 | 让模型直出（Q2=B，验收无法判对错） |
| R-3 | L1/L2 两套契约分开 | L1 面向模型（受 GBNF 约束，结构稳定），L2 面向宿主（可直接 `Transport.write`） | 单一契约（模型被迫理解寄存器语义，训练成本陡增） |
| R-4 | 相对 delta 而非绝对值 | "再亮一点"是相对语义；delta 天然可撤销 | 绝对值（需要模型知道当前值，且重复说会跳变） |
| R-5 | `turn` 原子性（有任何 confirm 项则整轮不写） | 避免"一半生效一半等确认"的中间态 | 部分执行（用户无法理解失败边界） |
| R-6 | 静音类 `confirm` + 话术覆盖 | 助手靠这支麦克风工作，失聪后无法语音自救 | 直接执行（演示事故）；彻底禁用（丢高频需求） |
| R-7 | LLM 关思考（双开关） | 实测 thinking on → 6.7 s 且丢动作 | 只给 `--reasoning-budget 0`（实测出现空 `actions`） |
| R-8 | `llama-server` 常驻 + 启动预热 | 冷启动 4.6 s vs 温缓存 1.2–2.2 s | 每轮 spawn（每次都冷启动） |
| R-9 | 评测分三层（文本/音频/真人） | 合成音频只能验链路，不能验识别鲁棒性 | 只做端到端（错误无法归因） |
| R-10 | vdevice 加 `GET /control/registers` 只读路由 | 回读校验需要读侧 | 解析 `/control/log` 帧（脆弱）；读真机（本版不做） |
| R-11 | **知识本体 `kb.ts` 是唯一真值**，规则表/词表/训练标签/评测期望四份产物都由它生成 | 四处手写必然漂移；本仓历史上参数表换版两次，漂移代价极高 | 各写一份（漂移无法发现）；把 kb 写成 YAML 文档（无法被 TS 引用与单测） |
| R-12 | 蒸馏**标签来自 kb、表述由教师改写** | 教师会幻觉；让学生学导师的表述多样性是对的，学导师的判断是错的 | 让 8B 直接标注（错误会被固化进学生）；纯模板（多样性不足，模型学成"只会背模板"） |
| R-13 | 微调从"条件分支"改为**主线必做** | 用户决策：小模型缺 EQ/场景先验，靠提示词补不动 | 只做 few-shot（实测 1.7B 自由描述会编动作） |
| R-14 | **数字接地**：`set` 的数值必须在用户原话里出现 | 需求方明确"小模型调不了 dB 数"；约束解码只保证语法 | 信任模型给的数（无法验收） |
| R-15 | **`eq` 频段寻址**作为独立动作类型 | 用户会直接点名"250 赫兹""3 k"，这类指令落不进 13 个语义维度 | 强行映射到 `muddiness`/`sibilance`（会说错段） |
| R-16 | 三档对比**取优者**作为默认推理档 | 避免"做了微调就必须用"的沉没成本错位 | 直接上微调模型（可能比 few-shot 更差） |

## 6. 风险与缓解

| 风险 | 触发条件 | 缓解 |
|---|---|---|
| 误唤醒 | 环境嘈杂、电视人声 | M6 用噪声/对话回放量化；参数可调 `keywords_threshold`；必要时叠 VAD 门控 |
| 规则覆盖率不足 | 用户说法超出 60 条词表 | 评测报告给出"未命中清单"，按清单扩表；扩表优先于微调 |
| 1.7B 编造动作 | 长句、多意图（"又闷又刺，还要响一点"） | `ops` 上限 4 项；`confidence < 0.5` 降级 `clarify`；评测集必须含多意图样本 |
| 延迟超标 | 4B 模型 / 开思考 / `say` 太长 | 硬上限 96 token；`say` 截断到 30 字；CI 里断言 P95 ≤ 2.5 s |
| 采集被别的程序占用 | 宿主同时在采 M001 音频做电平表 | `D6`：默认系统默认输入；失败时报 `busy` 并退出，不静默换设备 |
| 回读不一致 | vdevice 与 executor 状态不同步 | `E_READBACK_MISMATCH` + 回滚；评测里逐轮比对 |
| Python 依赖装不上 | 换机器 / 无网 | 模型与轮子都走 `fetch-models.mjs` 的清单；`--check` 提前暴露 |
| **训练数据泄漏** | 改写生成的相似句横跨 train/holdout | 按"知识条目 id + 模板 id"分组切分（不按行随机切），并对 holdout 做哈希去重；`data/manifest.json` 记录切分种子 |
| **教师引入错误** | 教师把"闷"改写成"明亮" | 标签永远来自 kb；改写结果只作 `text`，且用"关键词语义一致性"过滤（改写前后必须命同一条 kb 条目） |
| **训练超预算** | 5 000 条 × 3 epoch 在 4070S 上比预期慢 | 先跑 1 500 条 1 epoch 的消融看曲线，再决定 epoch 数与是否扩数据 |
| **微调后反而更差** | 过拟合窄分布 | R-16 三档对比取优；微调档不达标就退回 base+few-shot，并在验收报告里写明 |
| 学生模型与 base 不兼容 | 合并/量化出错 | 用 `llama-export-lora` 合并到 f16 后再量化；加载失败即视为 5.2 未完成 |
