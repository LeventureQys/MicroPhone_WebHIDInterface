## 1. 需求里的三处歧义（先摆事实，不替用户决定）

| 原话 | 问题 | 对应问题清单 |
|---|---|---|
| 「Qwen3.8-2B-Distill 这种较小模型」 | **没有这个模型**。Qwen3 系列只有 0.6B / 1.7B / 4B / 8B / 14B / 32B / 30B-A3B / 235B-A22B，没有 2B；"Qwen3.8" 也不是任何已发布版本号。DeepSeek-R1-Distill-Qwen 系列有 1.5B，但那是另一家模型 | Q3 |
| 「上位机软件暂时只需要一个MVP实现，不需要融入整个软件中」 | 两种读法：①语音能力做成独立侧车，宿主软件只留一个可选桥；②在宿主软件里做一个最小面板但只接参数写入 | Q1 |
| 「拿到的指令之后，需要检查一下内容…和功能无关的，需要排除」 | 排除靠什么：约束解码（结构层）还是规则表（语义层）还是微调（模型层）；三者的可测性完全不同 | Q2 / Q6 |

## 2. 本机实测（可复现）

### 2.1 自定义中文唤醒词确实可用（决定性证据）

**模型**：`sherpa-onnx-kws-zipformer-wenetspeech-3.3M-2024-01-01`（32.6 MB tar.bz2，GitHub release 直连可下）→ 解包后 int8 三件套共约 **5.0 MB**（encoder 4.78 MB + decoder 0.18 MB + joiner 0.065 MB）。

**关键事实：这个模型的建模单元是"拼音声母 + 韵母"，唤醒词由用户自己拼**。模型自带 `keywords.txt`：

```
x iǎo ài t óng x ué @小爱同学
x iǎo m ǐ x iǎo m ǐ @小米小米
```

所以要「小唐小唐」只需一行（我实测过，`t / áng / x / iǎo` 四个 token 都在 227 个 token 表里）：

```
x iǎo t áng x iǎo t áng @小唐小唐
```

**Python API（sherpa-onnx 2.0.3 实测签名，与本仓仓库里能查到的旧版教程不同）**：

```python
spotter = sherpa_onnx.KeywordSpotter(
    tokens=..., encoder=..., decoder=..., joiner=...,
    keywords_file=...,
    num_threads=2, sample_rate=16000, feature_dim=80,
    max_active_paths=4, keywords_score=1.0, keywords_threshold=0.25,
    num_trailing_blanks=1, provider='cpu', device=0,
)
stream = spotter.create_stream()
stream.accept_waveform(16000, samples)   # float32 [-1, 1]
stream.input_finished()
while spotter.is_ready(stream):
    spotter.decode_stream(stream)
    r = spotter.get_result(stream)       # 命中时是字符串"小唐小唐"，否则空
    if r: spotter.reset_stream(stream)
```

`KeywordSpotter.from_transducer()` 在 2.0.3 **已不存在**（官方老教程里的写法），只能用上面的构造器。

**检出演算**：用 Windows SAPI 合成「小唐小唐，把声音调亮一点」（16 kHz 单声道 16 bit，3.93 s），四组参数（`keywords_score ∈ {1,3}` × `keywords_threshold ∈ {0.1,0.25}`）全部命中：

```
score=1.0 threshold=0.25 -> hits=['小唐小唐']
score=3.0 threshold=0.25 -> hits=['小唐小唐']
score=1.0 threshold=0.1  -> hits=['小唐小唐']
score=3.0 threshold=0.1  -> hits=['小唐小唐']
```

### 2.2 误唤醒抽样：0/7

同一模型换成「小唐小唐」单关键词，喂模型自带的 7 条无关中文语句（文森特卡索 / 周望军 / 朱丽楠 / 蒋友伯 / 女儿 / 法国 / 见面会 / 落实 的组合）→ **0 次命中**。

同一组的**阳性对照**（用 `test_wavs/test_keywords.txt` 做关键词表）：0–2.wav 无命中（负样本），3–6.wav 各自命中本句短语，说明探针本身没坏：

```
正对照 test_keywords.txt : 3.wav=['文森特卡索','法国'] 4.wav=['蒋友伯','女儿'] 5.wav=['周望军','落实'] 6.wav=['朱丽楠','见面会']
自定义 小唐小唐          : 全部 []
```

结论：**自定义中文唤醒词路线可行**；误唤醒率需要更大语料才敢下结论（本组只有 7 条，属于抽样，不是指标）。

### 2.3 ASR：SenseVoice int8 快得超出预期

`pip install sherpa-onnx==2.0.3`（cp312 win_amd64 wheel，2 MB）+ `model.int8.onnx`（228.2 MB，hf-mirror 可下）+ `tokens.txt`：

```python
rec = sherpa_onnx.OfflineRecognizer.from_sense_voice(
    model=..., tokens=..., num_threads=4, use_itn=True, language='zh')
```

实测：

| 音频 | 时长 | 解码耗时 | 结果 |
|---|---|---|---|
| SAPI 合成「小唐小唐，把声音调亮一点」 | 3.93 s | **93 ms** | `小唐小唐把声音调亮一点。` |

模型加载 0.88 s（可常驻）。**99% 的时间预算留给了 LLM，ASR 不是瓶颈。**

### 2.4 小模型 + 约束解码（本机实测，由子代理在同一台机器上跑）

- 二进制：`llama-b12359-bin-win-cpu-x64.zip`（23.9 MB）。**老的 `-bin-win-avx2-x64.zip` 命名已废弃**，现在是运行时 ISA 派发的单一包，加载时实测 `ggml-cpu-alderlake.dll`（Raptor Lake：AVX2+FMA，无 AVX-512、无 VNNI）。依赖 `VCRUNTIME140.dll`（本机有 VC++ 2015-2022 x64 redist；干净机器需随包附带或装 redist）。
- 模型：`Qwen3-1.7B-Q4_K_M.gguf`（1.03 GB，`unsloth/Qwen3-1.7B-GGUF`；官方 `Qwen/Qwen3-1.7B-GGUF` 只有 Q8_0）。
- `llama-bench`，本机：**pp512 = 318.3 tok/s，tg128 = 43.5 tok/s @ -t 14**（`-t 20` 反而掉到 35.7 → 线程数必须取物理核 14）。0.6B：pp 829 / tg 111。
- **思考模式必须关**（Qwen3 默认开）：thinking on → 249 token / 6.7 s 且把动作丢了；thinking off → 35 token / 1.55 s。llama.cpp 里要 **`--reasoning-budget 0` 与 `--chat-template-kwargs '{"enable_thinking":false}'` 同时给**，只给前者会出现空 `actions`。
- 约束解码：`response_format: {"type":"json_schema", ...}` 或 `-jf schema.json`，**24/24 请求输出全部 schema 合法**，生成速度只降 8.3%。但**只保证语法**——实测 1.7B 会把「6 段 4.5 dB」写成 `input.gain=45`（0.6B 也写过），所以数值与参数 id 必须另有确定性守卫。
- 前缀缓存自动生效（`cache_n=174`），每次只 préfill 新 token；端到端 1.7B **平均 2.2 s（1.4–4.3 s）**，0.6B 平均 0.77 s。
- 质量：同一批 6 条中文口令，1.7B 能记住显式参数与相对量（`+3`），但对「人声太闷…高频提上来」会编出 6 条无关动作；**0.6B 连参数都认错**（「4.5 分贝」→ `input.gain=45`）。→ **1.7B 是实用下限，0.6B 只适合做速度对照。**

### 2.5 播报与测试语料：SAPI 一举两得

本机已装语音：`Microsoft Huihui Desktop`（zh-CN）、`Microsoft Zira Desktop`（en-US）；OneCore 侧还有 `MSTTS_V110_zhCN_HuihuiM / KangkangM / YaoyaoM`。

```powershell
$fmt = New-Object System.Speech.AudioFormat.SpeechAudioFormatInfo(16000, [System.Speech.AudioFormat.AudioBitsPerSample]::Sixteen, [System.Speech.AudioFormat.AudioChannel]::Mono)
$s = New-Object System.Speech.Synthesis.SpeechSynthesizer
$s.SelectVoice('Microsoft Huihui Desktop'); $s.SetOutputToWaveFile($out, $fmt); $s.Speak('小唐小唐，把声音调亮一点')
```

两个用途：①助手播报（零依赖、离线）；②**合成评测语料**（文本用例 → wav → 走完整条链路）。§2.1/§2.3 的 wav 就是这么来的，且 ASR 转写 100% 正确 → 说明"合成语料 → 全链路自动化回归"这条路成立。

### 2.7 宿主软件侧的接线点（读代码得到的事实）

- 参数真值在 TS：`src/renderer/src/device/registers.ts`（118 项预设区，止于 `0x2075`；`toRaw/fromRaw/defaultOf`），46 项标量派生在 `src/renderer/src/domain/params.ts`，场景在 `domain/scenes.ts`，音色曲线在 `domain/quick-controls.ts`。
- 写入口唯一：`AppStore.setParam(id, value)`（带 `readonly` 拒绝与 `sync !== 'ready'` 门控）、`setBands(bands)`（只写差异字段）、`setTone`、`setActiveScene`。见 `src/renderer/src/domain/state.ts:196` / `:254`。
- 通道契约：`ParamWrite {id, value}` 与 `EqBandWrite {band, field, value}`（`src/renderer/src/device/transport.ts:33` / `:50`）——**这就是语音指令最终要落成的形状**。
- 已有可编程的"落地靶"：虚拟下位子机控制面 `POST http://127.0.0.1:<ctl>/control/registers {"values":{"0x2025":2}}`（`tools/vdevice/sidecar.mjs:792`），可用来做端到端回读验证，不必先动真机。
- 半成品复用：`src/renderer/src/device/audio-meter.ts` 已在渲染进程抓过麦克风（`getUserMedia` + `AnalyserNode`）；若将来做应用内版本，可直接复用同一路流。
- 运行 TS 的坑：Node 24 能 `import()` 单文件 `.ts`，但**带相对 import 的模块不行**（`ERR_MODULE_NOT_FOUND`，实测 `params.ts → ../device/registers`）；仓库既有做法是 esbuild 打包（`scripts/probes/fulltest-p-truth.ts`）或 vitest（自带 TS + 别名解析）。

## 3. 未实测／待验证（进问题清单自决区，设计阶段收口）

### 3.1 音频采集
`sounddevice` 可用性只查了 wheel 存在，**没有在本机枚举/打开麦克风**。已知风险：独占模式冲突、USB 端点重枚举（本仓 `audio-meter.ts` 已经踩过，见 AGENTS.md「拔插后音频监听自愈」）、以及"助手自己用 TTS 播报 → 被自己听到"的回授。

### 3.2 VAD 端点
Silero VAD 未实测；`min_silence_duration` / 阈值需要按"1–6 s 口令"标定，否则会出现"没说完就切"或"等 2 s 才切"。

### 3.3 唤醒词误唤醒率
只有 7 条抽样（见 §2.2）。正式指标要用噪声/对话/电视回放（几十分钟量级）才有意义。

### 3.4 其他唤醒方案（未在本机验证，仅列事实供选型）
- **Picovoice Porcupine**：支持在控制台训练自定义中文词，效果好、资源占用低；但需要 AccessKey，免费额度面向个人/非商用，**商用需购买授权**，与"离线、可离线分发"的目标有摩擦（授权与联网激活细节未核）。
- **openWakeWord**：开源，但中文与自定义词需要自己合成数据训练，投入远大于本项目的 MVP 边界。
→ 默认选 sherpa-onnx（Apache-2.0、模型 32.6 MB、关键词就是一个文本文件），把 Porcupine 作为"效果不够时的替换项"记在问题清单里。

### 3.5 LoRA（将来才做）
工具链（Unsloth / LLaMA-Factory 原生 Windows + bitsandbytes）与 GGUF 适配器合并链路（`convert_lora_to_gguf.py` → `--lora` 或 `llama-export-lora` 合并后重新量化）**只做了文献核实，没有跑过**。规模估算：1k 样本 × 3 epoch ≈ 20–40 min（RTX 4070 SUPER，未实测）。
