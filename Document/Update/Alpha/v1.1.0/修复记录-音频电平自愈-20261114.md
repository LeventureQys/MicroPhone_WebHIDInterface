# 修复记录 — 拔插后音频电平监听失效（2026-11-14）

> 对应用户需求：「电平条是从驱动里监听出来的，但重新拔插之后这个监听有时候会失效；加个检查——如果系统下还有这个设备，就要以这个设备的驱动监听为准，而不是现在这样。」
>
> 设计变更记录 **R-38**、AGENTS.md §WebHID 接入「拔插后音频监听自愈」。本轮只改渲染进程音频链路，未动固件、协议与子模块。

## 1. 用户现象

M001 连着的时候电平条正常；USB 重新拔插（或设备复位、音频驱动重载）之后，电平条有时会一直躺在最底部，直到重开 app 才恢复。设备页诊断卡的「电平来源」这时显示 `设备上报 0x2057`（或一直停在旧输入名），但真机固件对 `0x2057` 恒回 0，所以电平条实际上是死的。

## 2. 根因

1. **端点重新枚举比 HID 慢**：Windows 拔插后 HID 先回来，自动连接立刻 `attach()` → `_startAudioLevels()`；此时音频端点还没枚举完，`getUserMedia` 报 `NotFoundError / NotReadableError`。旧实现把这个失败当成终态：`LinkState.audio.source = 'device'` + `setLevelPolling(true)`，退回恒 0 的 `0x2057`，且**再也没有人重试**。
2. **没人看采集死没死**：驱动重载 / 端点被系统重建时，`MediaStreamTrack` 只是 `ended`，`getFloatTimeDomainData` 继续返回旧缓冲（或全 0）；旧实现没有 `alive()` / `ended` 检查，采集对象一直"挂着"，电平条看起来冻结。
3. **attach 抢在端点前面时还会采错设备**：匹配不到提示词就退回系统默认输入（`matched=false`），端点回来后旧实现也不会切回设备自己的输入。

## 3. 改动

| 文件 | 变更 |
|---|---|
| `src/renderer/src/device/audio-meter.ts` | `AudioCapture` 增可选 `alive()` / `onEnded()`（真实实现盯 track `ended`、`AudioContext` `closed`）；`AudioMedia` 增可选 `watch()`（`mediaDevices.devicechange`）；`AudioLevelMeter` 每次出帧先验健康度，断了 `stop()` + 派 `onLost`；新增 `healthy()` / `find(hints)` / `watchDevices(cb)`；`start(hints,{strict})` 在 strict 下匹配不到设备端点直接报 `unavailable`，不退回系统默认输入；`AudioMeterInfo` 增 `id` |
| `src/renderer/src/device/link.ts` | 新增音频自检循环：`audioWatchMs` 默认 2 s，`onLost` / `devicechange` 立即触发（300 ms 合并），定时器只保留最早一拍；`LinkAudioState.source` 增 `'retrying'`；打开失败按 `_devicePresent()` 分流——设备还在就 `'retrying'` + 保持 `setLevelPolling(false)`，按 `audioRetryMs`（300 ms 起指数退避、封顶 5 s）重开；只有 `denied`（停手不空转）或设备确实不在才退回 `'device'` + 轮询；重开前 `find()` 确认端点已回来、重开用 `strict:true`；采集活着但 `matched=false` 时端点一出现就切过去；新增 `dispose()`；`DeviceLinkOptions` 增 `audioWatchMs` / `audioRetryMs` / `onEvent` |
| `src/renderer/src/ui/views/device-view.ts`、`i18n/{zh,en}.ts` | 「电平来源」行新增「正在重新打开音频输入（设备还在，自动重试）」（`device.audio.retrying`） |
| `src/renderer/src/main.ts` | 传 `onEvent` → 控制台 `[audio-level]` 日志（诊断用） |
| `tests/unit/{audio-meter,link,device-view-diag}.test.ts` | 新增 11 条用例（见 §5） |
| `Document/Update/Alpha/v1.1.0/设计文档.md`、`AGENTS.md` | R-38、§WebHID 接入段落 |

判定口径（按用户要求）：**只要设备还在系统里（HID 句柄仍打开且未被判掉线），电平来源就必须是设备音频输入**；`0x2057` 只在权限被拒或设备确实不在时兜底。

## 4. 行为对照

| 场景 | 改前 | 改后 |
|---|---|---|
| attach 时音频端点还没枚举完 | `source='device'` + 轮询，永久不重试 | `source='retrying'`，轮询保持关闭；端点回来即 strict 重开（300 ms 起退避，封顶 5 s） |
| 拔插后自动连接成功、音频端点晚 1–3 s 出现 | 同上，电平条躺底 | 自检循环 / `devicechange` 发现端点 → 重开，无需用户操作 |
| 驱动重载导致 track `ended` | 采集僵尸，电平冻结 | 出帧时发现健康度 false → `onLost` → 立即重开 |
| attach 时只匹配到系统默认输入（`matched=false`） | 一直采默认输入 | 设备端点出现后自动切到设备输入（strict） |
| 麦克风权限被拒 | `source='device'` + 轮询 | 同左（硬失败，但不再空转重试） |
| 设备确实拔掉 | `source='device'` + 轮询 | HID 掉线照常降级，音频停止；不误开默认输入 |

## 6. 待真机拔插复测

本机能连到 M001（固件 0.0.5.0），但不便在用户使用期间物理拔插，以下三条留给现场复测：

1. 真机插着 → 电平条正常 → 拔线 → 插回：诊断卡应在 1–3 s 内从「正在重新打开音频输入」回到「音频输入：麦克风 (USB Audio Device) (0a67:0010)」，期间「设备轮询」保持「关」，`timeouts/retries` 不应因音频重试上涨（重试不发 HID 帧）。
2. 设备插着但把 Windows 麦克风权限关掉 → 应显示「麦克风权限被拒绝（电平退回设备上报）」且不再每 2 s 撞一次 `getUserMedia`。
3. 换 USB 口插拔（音频端点 id 可能变化）：应自动切到新端点，不需要重开 app。
