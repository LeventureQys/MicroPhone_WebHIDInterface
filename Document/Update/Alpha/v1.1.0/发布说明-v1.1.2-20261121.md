## 2. 怎么用（给客户）

1. 把 `MicStudio-1.1.2-portable.exe` 拷到目标机（Windows 10/11 x64），**双击即可**，不需要安装任何东西。
2. 插着 M001（`VID 0A67 / PID 0010`）时启动后自动连接、自动同步参数，顶栏显示「已连接 / 已同步」。
3. 配置与启动日志在 **exe 同级的 `MicStudioData\`**（便携模式，不写系统 AppData）；出问题先看 `MicStudioData\startup.log`。
4. 没有真机时界面显示「演示数据」，可直接看交互；虚拟桥接通道需要另起 `pnpm run vdevice`，不随包分发。
5. 双击被拦：SmartScreen →「更多信息 → 仍要运行」；公司 App Control 策略需要 IT 放行；窗口一闪而过时用
   `cmd /c start "" "<exe 完整路径>" --no-sandbox`。

## 3. 相对 1.1.1 的变化

### 3.1 参数表 V0.3（`Document/Update/hardware/v0.0.6/`）

| 项 | 地址 | 变化 |
|---|---|---|
| MIC 均衡器模式范围 | `0x2026` | `[0,4]` → `[0,5]`（界面仍不暴露该控件） |
| 三分频分频点默认 | `0x2061/0x2062` | 50/50 → **1000/3000**，默认不再出现「分频点无效」 |
| 三分频三区 preGain 默认 | `0x2063/68/6D` | 0 → **128（1.28）** |
| RGB 开关 / 模式（新增） | `0x2072/0x2073` | 默认 1 / 0，模式 `[0,7]`；高级参数新增「灯效」分区 |
| NoiseGate / 3BandDrc 使能（新增） | `0x2074/0x2075` | 默认 1；**这就是 buglist 要求的模块 bypass 开关** |

配套：预设区 114 → **118 项**，`sync()` 的 `0x13` 连读改为 118 字；界面参数 42 → **46 项**。

### 3.2 旁通从「中性参数近似」升级为真实使能位

- 噪声门、三分频动态：改成真实开关（关掉即直通），不再把阈值钉 -91 dB / 把 preGain 掐成 0。
- 均衡器：协议确实没有全局 enable，仍用 7 段 `enable` 实现真旁通。
- 一键场景：四个固定场景与「自定义」都会把两个使能位写 1，并纳入场景高亮比对。

### 3.3 上一轮（2026-11-13 / 11-14）未提交的改动一并入包

耳机/麦克风增益去抖、USB 探测改事件驱动（5 s 兜底、只按 VID/PID）、写合并改尾沿 300 ms + 写帧间隔 200 ms、
界面改版（阈值直读 dB / 5 档音色 / 场景顺序 / 输入开关上主界面 / 只有自定义可拖曲线）、拔插后音频电平自愈。

## 5. 已知限制（重要）

1. **未签名**：目标机首次运行会弹 SmartScreen，点「更多信息 → 仍要运行」；被安全软件隔离需加信任。
2. **测试机固件侧问题**：V0.0.6 的 DFU 包刷不进这台 M001——界面 DFU 把 658/658 块写完但设备没启动新版本，
   之后从 Bootloader 续刷、以及 python 直连工具都在**随机偏移**挂死（1089/2631、2275/2631 块）。
   现象与 `真机DFU首刷记录.md` §8 的「QSPI XIP 擦写/取指互锁」一致，属固件侧问题。
   **设备当前停在 Bootloader**，需要 J-Link（SWD）整片刷写恢复；仓库已备好
   `scripts/flash-jlink.mjs` + `scripts/probes/install-jlink-devices.py`，只差仿真器和四根线。
   详见 `Document/Update/hardware/v0.0.6/固件刷写失败记录-20261121.md`。
3. **真机全量测试（参数矩阵）未做**：设备刷坏前只完成了「参数还原成 V0.3 默认值」的一次性验证；
   46 项界面值 ⇄ 寄存器真值的逐项对账要等设备恢复后补（探针 `scripts/probes/real7-id.js` 已备）。
4. **三分频听感**：第六轮联调发现固件预设结构体从 `0x205B` 起整体右移 2 字，上位机只能保证可写可回读，
   听感是否生效仍需固件确认结构体偏移。
5. 本机（开发机）开启了 Smart App Control / WDAC：未签名 exe 直接双击会被拦（退出码 `0x80000003`），
   验证时用 `cmd /c start "" "<exe 完整路径>" --no-sandbox`；目标机是否同样需要取决于那台机器的策略。
