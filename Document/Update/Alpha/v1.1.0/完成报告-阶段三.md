## 3. 契约修订汇总

全部 20 条修订见 `设计文档.md` §12。开发期真正改变了实现方向的是前 5 条：

| # | 修订 | 影响面 |
|---|---|---|
| R-1 | 补位零规则（`UnitID=0` + `Func=0` 不可能是合法帧） | 帧层；不做则每帧刷诊断 + 跨包错位 |
| R-9 | 真机白名单两段式 | 主进程 + 渲染进程 filters；原设计在真机路径永不命中 |
| R-13 | `sync()` 设备信息读 46 个地址 | 会话层；原 11 个地址拿不到 VID/PID/SN |
| R-15 | `0x02` ACK 可终止任何在途请求 | 会话层；否则"读不存在的地址"会把链路打成 error |
| R-17 | `DeviceBoundTransport` + 入站分流 | 通道层；否则 DFU 状态帧被参数会话吞掉，必然 `probeFailed` |

这五条都是**实现期才暴露的**：任务书按契约写、SubAgent 照着实现、矛盾在执行时立刻显形。评审阶段无法靠读文档发现。
