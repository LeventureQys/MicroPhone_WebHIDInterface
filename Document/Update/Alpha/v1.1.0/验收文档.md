## 4. 验收项

> 每项格式：**目的 / 步骤 / 期望结果 / 通过标准 / 失败标准 / 证据**。
> 编号规则：A 系列 = 功能与协议；B 系列 = 回归与界面。验收报告必须逐条给出"通过 / 失败 / 阻塞"。

### A1 门禁三绿（R10-1）
- 目的：确认可编译、可测试、可打包。
- 步骤：依次执行 `& $node $pnpm run typecheck`、`& $node $pnpm run test`、`& $node $pnpm run build`。
- 期望：三条命令退出码均为 0；`out/{main,preload,renderer}` 均生成。
- 通过标准：三条命令全绿且 `out/renderer/index.html` 存在。
- 失败标准：任一命令非 0；或有 `error TS` / 失败用例。
- 证据：三条命令的完整 stdout 尾部（含用例统计行）。

### A2 协议层与镜像层覆盖率（R10-2）
- 目的：协议与镜像代码被单测覆盖 ≥ 90% 行。
- 步骤：`& $node $pnpm run test:coverage`。
- 期望：**聚合**行覆盖率 ≥ 90%（vitest 阈值 90/85/80/90 全过、退出码 0），且**逐文件行覆盖率 ≥ 85%**；报告里必须列出每个文件的行/分支百分比与最低值。
- 通过标准：聚合 ≥ 90% 且没有单文件 < 85%。
- 失败标准：聚合 < 90%；或任一单文件 < 85%；或工具缺失且未按 SubStage 5.3 §4.2 声明退化方案。
- 证据：覆盖率表格原文（含每文件百分比）。
- 口径说明：`device/dfu/controller.ts` 属**编排层**（选包/确认/重试/状态映射），不是协议或镜像算法，其分支多由端到端路径覆盖；R10-2 的"协议层与镜像层"指 `proto/**`、`dfu/{frame,image,session}.ts`、`registers.ts`，这四类必须逐文件 ≥ 90%。

- 期望：① 至少出现一条写帧，地址落在 `0x2027`–`0x2049`（如段 3 的 Gain 是 `0x2034`）；同段一次改多个可写字段应被合并成一条 `0x11`（**可写字段是 4 个：type/freq/gain/q，`enable` 按 B7 不写，所以 count 最多 4，不是 5**）；② 只发变化的字段（未变的段/字段不出帧）；③ 整份日志里出现的 EQ 地址全部落在 `0x2027`–`0x2049`，内部段（无寄存器）不出现。
- 通过标准：① 有写帧且地址正确；② 无越界地址。
- 失败标准：改 EQ 一帧都不发（"仅本地"），或出现 `0x2027`–`0x2049` 之外的 EQ 地址。
