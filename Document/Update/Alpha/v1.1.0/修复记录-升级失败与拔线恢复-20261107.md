# 修复记录 — 升级失败 / 拔线后“只能重开 app”（2026-11-07）

> 对应设计变更记录 **R-26**、AGENTS.md 已知坑 **31**。本轮只改主机侧（渲染进程），未动固件与子模块。

## 1. 用户现象

固件升级失败，或者升级中/平时把 USB 拔掉之后：

- 点固件抽屉的「立即重试」「重插后再试」都没反应，错误一直是 `设备通道异常` 或 `没有已连接的设备`；
- 回设备页点「打开」也打不开（停在「同步失败」）；
- 只有关掉 MIC STUDIO 重开才能恢复。

## 2. 复现与取证（修复前）

用真实类（`DeviceLink` + `WebHidTransport` + `FakeHidDevice`，以及 `FirmwareController` + 死句柄）写了 5 组探针，修复前全部成立：

| 探针 | 观察 |
|---|---|
| A | `suspendForDfu()` 之后（= 升级失败且未 resume）：`transport.write()` **一帧都发不出去、也不报错**；`store.sync` 仍是 `ready`；`disconnect` 事件**不产生任何错误**；`link.status` 永久停在 `'dfu'` |
| B | 失败后 `attach()` 立即失败（`errorCode: 'sync'`），而同一台设备另起一条 `WebHidTransport` 立刻 `ready` → 卡的是宿主状态，不是设备 |
| C | 再 `attach()` 一次仍然失败；`session.refresh()` **一次都没调用**，也就永远拿不到拔插后的新句柄 |
| D | 只有 `detach()`（设备页点「关闭」）能清掉挂起 → 实际只有“关闭→打开”或重开 app 能救 |
| E | 死句柄下 `start()` → `error.kind='channel'`；`resumeAfterDfu()` 调用 0 次、`awaitReenumeration()` 0 次；「立即重试」往同一根死句柄发帧，「重插后再试」只 `attach` 旧 id |

全量 643 项用例当时全绿——**这条路径没有任何用例覆盖**。

## 3. 根因

1. **失败收场不恢复链路**：`FirmwareController.start()` 只在 `run()` 成功后才调 `resumeAfterDfu()`；失败/中止只 `setDfuActive(false)`，`DeviceLink.status` 停在 `'dfu'`、`WebHidTransport._suspended` 永久为真 → 写被静默丢弃、拔线被吞、`_handleDrop()` 早退、界面仍显示“已同步”。
2. **`open()` 在挂起时直接返回**：`suspend()` 不改 `state`（仍 `'ready'`），`attach()` 里的 `transport.open()` 命中早退；`readAll()` 的入站字节又被 `_suspended` 拦掉 → 每条回读都超时 → `_failSync()`。
3. **重试不重新枚举句柄**：`reconnect`（= `awaitReenumeration()`）只在 EnterDfu 拿到 ACK 后才调用；句柄已死时 EnterDfu 的 `sendReport` 直接抛，永远走不到重枚举。`replugAndRetry()` 又只 `attach(旧 deviceId)`，从不 `refresh()`。
4. **设备表不跟热插拔**：`WebHidSession` 无 `hid.connect/disconnect` 订阅，拔插后句柄表与 `opened` 都是旧值。

## 6. 真机待验证（需要人工，脚本无法代替）

1. **升级中途拔线**：升级到约 30% 时拔线 → 等 3 s → 插回 → 直接点「立即重试」（不要关 app）。
   预期：先出现一次 `设备已拔出或重新打开失败`（若插回慢了），再点一次即重新枚举并继续；全程不需要重启 app。
2. **升级失败后回工作台**：判据：顶栏不再停在“已同步/已连接”假象；设备页显示「同步失败 + 可能停在升级模式」；插回后点「打开」能恢复（不再需要先点「刷新」）。
3. **中止**：升级中点「中止升级」→ 应回到 `failed/aborted`，链路可继续操作，可再点「立即重试」。
4. **长时静默**：升级失败后不插回设备，观察 1 分钟：不应出现界面卡死；关窗应可以正常退出（升挂已由 `finally` 释放）。

## 7. 遗留（未做）

- `WebHidSession` 仍没有订阅 `navigator.hid` 的 `connect/disconnect`：**设备列表**不会自动刷新（设备页开着时靠「刷新」按钮）。但“拔插后自动连回来”已由 2026-11-07 新增的后台自动连接覆盖（`device/auto-connect.ts`，设计 §12 R-27）：插上 M001 后 1.5 s 内自动 `connect('native') + attach()`，不需要用户操作；升级期间该后台任务会被 `FirmwareController` 暂停，收场后再武装。
- `DfuSession.dfuSettleTimeoutMs`（20 s）与收尾重连仍可能重叠：极端情况下 `complete()` 会因 phase 已 `failed` 而无效，界面显示 `settle` 而实际已升级成功。属既有问题，本轮未动。
- 中止按钮只覆盖 App 模式（`entering/probing/writing`）；`0x05` 之后设备在收尾，主机不提供中断（协议约束）。
