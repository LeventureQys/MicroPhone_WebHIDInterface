# 验收文档 - Alpha v1.0.0

对应设计文档：`Document/Update/Alpha/v1.0.0/设计文档.md`
对应开发文档：`Document/Update/Alpha/v1.0.0/开发文档/SubStage_1.1.md` … `SubStage_4.2.md`

## 1. 验收范围

**覆盖**：工程构建与类型检查、单元测试、开发态启动、打包产物启动（Windows portable + nsis + win-unpacked）、6 个页面截图取证、36 个参数控件的初值与联动、EQ 曲线交互、双语切换、参数写入链路（Mock）。

**不覆盖**：真实 HID 设备联调、macOS（dmg）与 Linux（AppImage）产物运行、代码签名与公证、安装包升级逻辑、性能压测（多设备并发）。

## 2. 验收环境

- 操作系统：Windows 11 专业版 26200（会话 1，桌面会话可用）
- Node：`v24.21.0`（绝对路径见 `AGENTS.md`）；
- pnpm：`11.7.0`
- 依赖版本冻结：`electron@33.4.11`、`electron-vite@6.0.0`、`vite@5.4.21`、`vitest@1.6.1`、`happy-dom@20.14.6`、`electron-builder@26.15.3`
- 运行前置环境变量：`MICSTUDIO_USER_DATA=D:\WorkShop\MicroPhone_WebHIDInterface\.userdata`
- 打包前置环境变量：`ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/`、`ELECTRON_BUILDER_BINARIES_MIRROR=https://npmmirror.com/mirrors/electron-builder-binaries/`
- 无真实麦克风设备；电平数据来自 `MockTransport`

## 3. 前置条件

1. 仓库工作区干净可构建（`node_modules` 已安装，`node_modules/electron/dist/electron.exe` 存在）。
2. 已执行 `pnpm run build`，`out/main`、`out/preload`、`out/renderer` 三处产物存在。
3. `D:\WorkShop\MicroPhone_WebHIDInterface\.userdata` 可写（脚本会自动创建）。
4. 记录本机 `%APPDATA%` 下的 Electron 目录已被移开（若存在旧崩溃残留），实际不影响：应用使用 `.userdata`。

## 4. 验收项

### A1. 全量构建通过
- 目的：确认三端构建链路可用。
- 前置条件：依赖已安装。
- 操作步骤：执行 `pnpm run build`，输出重定向 `artifacts/build.log`。
- 期望结果：退出码 0；日志含 `build` 完成信息；`out/main/index.js`、`out/preload/index.js`、`out/renderer/index.html` 均存在。
- 通过标准：退出码 0 且三个产物文件存在（`Test-Path` 全部 True）。
- 失败标准：任一产物缺失，或日志出现 `error` 级报错。
- 证据要求：`artifacts/build.log` 尾 30 行 + 三个产物的 `Length`。

### A2. 类型检查与单元测试
- 目的：确认契约实现无类型漂移、逻辑有测试覆盖。
- 前置条件：A1 通过。
- 操作步骤：`pnpm run typecheck`；`pnpm run test`，输出重定向 `artifacts/test.log`。
- 期望结果：typecheck 退出码 0；vitest 报告 `Test Files ≥ 8 passed`、`Tests ≥ 45 passed`、0 failed。
- 通过标准：两项均退出码 0，且 vitest 输出的 failed 数为 0。
- 失败标准：任一失败；或测试文件数 < 8（说明某 SubStage 未交测试）。
- 证据要求：`artifacts/test.log` 的汇总段（Test Files / Tests / Duration）。

### A3. 开发态启动
- 目的：确认 Electron 主进程能在本机起窗口。
- 前置条件：A1 通过；`MICSTUDIO_USER_DATA` 已设置。
- 操作步骤：`pnpm run dev`（或 `node_modules\electron\dist\electron.exe . --no-sandbox`，环境变量同上），运行 20 秒。
- 期望结果：进程持续存活；窗口标题 `MIC STUDIO`；控制台无 `APPCRASH` 事件；渲染端打印 `[boot] renderer ready`（若保留该日志）。
- 通过标准：存活 ≥ 20 秒且窗口标题正确，`artifacts/startup-dev.log` 中无 `did-fail-load`。
- 失败标准：进程退出、窗口白屏、日志出现 `did-fail-load` 或主进程异常。
- 证据要求：`artifacts/startup-dev.log`、进程存活截图或 `Get-Process` 输出。

### A4. 打包产物启动（win-unpacked）
- 目的：确认打包后的应用能运行。
- 前置条件：A1 通过，`pnpm run dist:win` 已成功。
- 操作步骤：设置 `MICSTUDIO_USER_DATA`，启动 `release\win-unpacked\MicStudio.exe`，等待 15 秒。
- 期望结果：进程存活；窗口显示主界面（截图非白屏）。
- 通过标准：进程存活 ≥ 15 秒 + 截图 `artifacts/startup-packaged.png` 中可见顶栏、导轨与内容。
- 失败标准：进程退出、白屏、崩溃事件。
- 证据要求：截图 + `Get-Process` 输出。

### A5. 免安装包 / win-unpacked 启动
- 目的：验证打包后的可运行形态。
- 前置条件：`release\MicStudio-1.0.0-alpha.0-portable.exe` 与 `release\win-unpacked\MicStudio.exe` 存在；`ELECTRON_RUN_AS_NODE` 已从环境中清除。
- 操作步骤：先用 `--hold=12000` 启动 `win-unpacked\MicStudio.exe`（环境变量 `MICSTUDIO_USER_DATA` 指向可写目录），记录 `startup.log`；再尝试直接运行 portable exe。
- 期望结果：win-unpacked 版本 12 秒后自行退出、日志含 `boot packaged=true` / `window-created` / `renderer: [boot] renderer ready`；portable 版本窗口出现（本机沙箱环境预期失败，见 §6）。
- 通过标准：win-unpacked 日志链路完整且退出码 0；portable 若本机无法启动，必须记录为**阻塞**并附失败现象，不得标通过。
- 失败标准：win-unpacked 无窗口或日志缺 `window-created`。
- 证据要求：`artifacts/startup-packaged.log` + `artifacts/packaged-meter.png` / `packaged-eq.png`。

### A6. 六页面截图取证
- 目的：证明每个页面都能渲染。
- 前置条件：A1 通过。
- 操作步骤：`pnpm run screenshot`。
- 期望结果：`artifacts/shot-meter.png`、`shot-input.png`、`shot-eq.png`、`shot-dynamics.png`、`shot-drc.png`、`shot-settings.png` 六个文件，每个 > 20KB。
- 通过标准：6 个文件都存在且体积达标；每张图肉眼可见对应页面特征元素（电平页有双柱、EQ 页有橙色曲线与 7 个节点）。
- 失败标准：任一缺失、体积过小（白屏）、页面内容错位。
- 证据要求：6 张图 + 脚本汇总表输出。

### A7. 电平页功能
- 目的：验证"实时电平显示"。
- 前置条件：应用已启动，位于电平页。
- 操作步骤：观察 10 秒；切换场景为「静音」观察 5 秒；切「音乐」观察 5 秒。
- 期望结果：柱体与数值持续变化；静音时接近 -72 dBFS；音乐时在中高位波动；峰值线可见。
- 通过标准：三阶段行为符合上述描述；状态卡写入计数随参数改动增长。
- 失败标准：柱体静止不动、数值与柱体不一致、出现 NaN。
- 证据要求：三张不同场景的截图（可复用 A6 的 meter 图 + 追加两张）。

### A8. 输入页参数
- 目的：验证只读与可调参数的初值及写回。
- 前置条件：位于输入页。
- 操作步骤：核对 Gain.Mic=5、Gain.Hp=0（只读，无滑块）；核对 NoiseGate 六项初值 -70 / 0.333 / 10 / 200 / 12 / 150；拖动阈值到 -50，切页再回来。
- 期望结果：初值一致；只读项无滑块且显示"只读"徽标；改动后值保持 -50。
- 通过标准：全部初值正确 + 改动可保持 + 顶栏同步状态有变化。
- 失败标准：任一初值不符、只读项可编辑、改动丢失。
- 证据要求：截图 + 控制台 `[store]` 或写入计数变化记录。

### A9. EQ 曲线与交互
- 目的：验证核心视觉与交互。
- 前置条件：位于 EQ 页。
- 操作步骤：截图；拖动节点 3 到 +6 dB；双击节点 3；滚轮悬停节点 5；键盘聚焦节点 1 后按 ↑ ×5；点「全部归零」。
- 期望结果：曲线随拖动变形并最终拉平；双击后该段增益 0、Q 0.7；滚轮改变 Q 且页面不滚动；键盘改变增益；归零后曲线贴近 0 dB。
- 通过标准：五个动作全部产生预期变化，段列表数值与画布一致。
- 失败标准：拖动无响应、列表与画布不同步、归零无效。
- 证据要求：交互前后各一张截图 + 段列表数值记录。

### A10. 动态页参数
- 目的：验证压缩器与限制器控件。
- 前置条件：位于动态页。
- 操作步骤：核对 Comp 六项初值 0 / -60 / 0.0005 / 0.1 / 6 / 1；Limit 三项 -60 / 0.0005 / 0.05；各拖动一个滑块。
- 期望结果：初值一致；拖动后数值按步进变化并可保持。
- 通过标准：初值全对 + 改动生效。
- 失败标准：任一初值不符或改动无效。
- 证据要求：截图。

### A11. 分频页参数
- 目的：验证 3BandDrc 三区与分频点联动。
- 前置条件：位于分频页。
- 操作步骤：核对 fc1=1000、fc2=3000；核对三个区各 5 项初值 1.28 / 0 / 10 / 20 / 10；把 fc1 调到 5000（大于 fc2）。
- 期望结果：初值一致；三张区卡副标随 fc1/fc2 实时更新；fc1 > fc2 时出现冲突提示（`drc.conflict` 文案 + 卡片描边变化）。
- 通过标准：初值正确 + 副标联动 + 冲突提示出现。
- 失败标准：副标不更新、无冲突提示。
- 证据要求：两张截图（正常 + 冲突）。

### A12. 设置页与恢复默认
- 目的：验证全局操作。
- 前置条件：曾修改过若干参数。
- 操作步骤：点「恢复默认参数」。
- 期望结果：所有被改参数回到默认值；EQ 回到 14 段默认频点。
- 通过标准：抽查 3 个参数（NoiseGate.threshold_db、Comp.Rate、drc3.mid.ratio）与 EQ 频点全部复位。
- 失败标准：部分参数未复位。
- 证据要求：操作前后截图或数值记录。

### A13. 双语切换
- 目的：验证 i18n 全量覆盖。
- 前置条件：应用运行中。
- 操作步骤：切到 EN，依次访问 6 个页面；再切回中文。
- 期望结果：所有标题、标签、按钮、单位、EQ 列表列头均为英文；无中英混排残留；EQ 曲线数据不变。
- 通过标准：6 页均无中文残留（`Comp.Rate` 与 `Gate.ratio` 等协议原名保持原样属预期）。
- 失败标准：出现未翻译文案（除协议原名）。
- 证据要求：EN 状态 6 页截图（至少 3 张）。

### A14. 打包产物完整性
- 目的：确认交付物齐全。
- 前置条件：`electron-builder --win portable` 已执行。
- 操作步骤：列出 `release/` 目录。
- 期望结果：`MicStudio-1.0.0-alpha.0-portable.exe`（60–120MB）与 `win-unpacked/MicStudio.exe` 均存在；`MicStudio Setup <ver>.exe`（nsis）在能访问 GitHub 的环境下生成。
- 通过标准：前两者存在且体积正常；nsis 若缺失，必须在验收报告中标为**未验证**并写明原因（本机为 NSIS 执行受限，见 §6）。
- 失败标准：portable 或 win-unpacked 缺失。
- 证据要求：`Get-ChildItem release` 输出。

### A15. 稳定性回归
- 目的：确认无崩溃与明显泄漏。
- 前置条件：应用运行中。
- 操作步骤：6 个页面往返 3 轮，每页停留 5 秒，期间反复拖动 EQ 节点 10 次。
- 期望结果：无崩溃、无白屏、控制台无 error 级日志；内存增长 < 150MB。
- 通过标准：全程无异常 + 内存增量达标。
- 失败标准：崩溃、白屏、内存持续大幅增长。
- 证据要求：操作记录 + 前后内存读数（任务管理器或 `Get-Process` WorkingSet）。

## 6. 失败与阻塞处理

- **A1/A2 失败** → 退回阶段三，定位到具体 SubStage。
- **A3/A4/A5 失败** → 先确认 `MICSTUDIO_USER_DATA` 是否生效（打印 `app.getPath('userData')`）；仍失败退回开发。
- **A6 白屏** → 查渲染端 console 转发日志，定位抛错文件。
- **A7–A13 功能失败** → 定位到对应 SubStage（A7→3.2，A8/A10/A11/A12→3.4，A9→3.3，A13→2.3）。
- **A14 打包失败** → 确认镜像环境变量，重试一次，仍失败记录并上报。
- **A15 失败** → 记录复现步骤，定位泄漏来源。
- 无法执行的项（如 macOS/Linux、真实 HID）必须标为**未验证**，不得标通过。

## 7. 回归范围

- 不覆盖：Alpha 之前无历史版本，无历史功能回归需求。
