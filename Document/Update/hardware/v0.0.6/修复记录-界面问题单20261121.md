## 2. 上位机改动明细

### 2.1 主界面（`ui/views/console-view.ts`）

- **快速调音**由「两个阈值 + 音色 + 三个输入开关」变成「三行阈值（各带开关）+ 音色 + 三个输入开关」：
  - 行内开关复用 `macroSlider` 新增的 `toggle` 选项（`ui/controls.ts`），开关本体是 `switchControl` 的**无文案变体**（`switch-row--bare`，无障碍名走 `aria-label`），落在标题行读数的左侧。
  - 三个开关/阈值写的都是高级参数里同一个参数 id（`noisegate.Enable` / `comp.Enable` / `limit.Enable`、`noisegate.threshold_db` / `comp.Threshold` / `limit.Threshold`），因此**联动是同一份状态**，回填只靠 `store.onChange` 里的 `setValue/setToggle`。
- **快捷开关**卡只剩「环境降噪 + 档位」；限幅器（防爆音）开关随阈值搬进快速调音，避免同屏两个开关写同一个位。
  行标题用**「防爆音」**而不是「限幅器阈值」：第一版打出来叫「限幅器阈值」，用户反馈"界面上的防爆音没了"（2026-11-22），
  已改回产品叫法；高级参数里仍叫「限幅器」，两处指同一个模块（`0x2051` / `0x2053`）。
- **音色曲线**卡头右侧并排「复位」「逐段精调」：
  - 「复位」只在 `tone === 'custom'` 时可用（`aria-disabled` 同步），点击后 `withEqReset()` → `store.setBands()` + `setCustomEq()`，曲线/段值与设备一起刷新；
  - 「逐段精调」改为 `api.openAdvanced('eq')`，抽屉直接落在「均衡」一节。
- 电平表输出通道传 `showPeak: false`（问题单 10）。

### 2.2 抽屉跳转（`app/shell.ts`、`ui/views/advanced-view.ts`）

- `ShellApi.openAdvanced(section?)` / `openPanel(id, { section })`：打开抽屉后**下一帧**在抽屉内部 `scrollIntoView`，避开吸顶跳转条（分区自带 `scroll-margin-top`）。
- `AdvancedSectionId` 由 `advanced-view.ts` 导出（`input / dynamics / eq / drc / lighting`），主界面只引类型，不产生运行时依赖。
- 跳转条高亮沿用抽屉自己的 scroll 捕获监听，无需额外通知。

### 2.3 复位落点（新增 `domain/eq-reset.ts`）

- `eqResetBands()`：从 `DEFAULT_BANDS`（寄存器表派生）取前 7 段的类型/频点，覆盖 `gain = 0`、`q = 0.7`；
- `withEqReset(bands)`：把复位值套到现有 14 段上，设备内部段（8–14）原样保留；
- 与参数表的**出厂默认**（Band-3 增益 −3.5 dB、Q 0.8/1.5/1.0/1.0/0.7）刻意区分：
  参数表是设备上电加载的预设，问题单要的是「复位成一条平直曲线」，因此只在 UI 动作里覆盖，不动 `registers.ts`。
- 高级参数「全部复位」（`ui/views/eq-band-table.ts`）与主界面「复位」共用这一个 preset。

### 2.4 电平表（`ui/meter.ts`）

- `MeterChannel.showPeak?: boolean`（缺省 true）：false 时既不画峰值读数，也不画峰值保持线；RMS 与 LED 段不变。缺省行为与旧实现逐字一致（单测「leaves existing visuals unchanged…」仍然通过）。

### 2.5 文字与设置页

- `param.gain.Hp.label`：耳机增益 → 耳机音量（中英）；`param.noisegate.ratio.label`：扩展比 → 压缩比（中英）。
- 高级参数「噪声门」卡新增一行说明（`module.noisegate.ratioHint`）：压缩比是什么、0.05/0.99 分别意味着什么、**开关 + 阈值 + 压缩比三样都要下发**。
- 三个模块的 `*.bypassHint` 改写成「与主界面联动，两处任改一处」。
- `console.tune.desc` 改成「三个阈值都带开关，一个音色，再加三个输入开关」；删掉随「防爆音」开关一起退役的 `console.hint.limitOn/limitOff`。
- 设置页 VID 占位符 `0x352F` → `0x0A67`（问题单 8/9）。

## 4. 判给下位机的 4 条（附依据）

| # | 现象 | 为什么不是上位机 | 建议固件侧 |
|---|---|---|---|
| 2 | 旋钮调最小不是 0、最大不是 100 | `0x2023`（MIC 音量）/ `0x205A`（监听音量）在参数表里是 `[0,100]` 的**只读**项，上位机只显示设备回读值；两头到不了端点是旋钮 ADC → 0..100 的映射 | 校准 ADC 端点（或做两段线性补偿），让最小值回 0、最大值回 100 |
| 7 | bootloader 升级时 USB 设备名带「不良第三方信息」 | 设备名来自 Bootloader 的 USB String Descriptor（Product String），主机侧只读 | 改 Bootloader 描述符字符串 |
| 8 | bootloader 的 VID 要统一成 `0x0A67` | 同上，VID 在描述符里；上位机白名单本来就是 `0x0A67/0x0010`，不依赖 bootloader 的旧 VID | Bootloader 描述符 VID 改 `0x0A67`（改完上位机不用动） |
| 11 | 噪声门「没有效果」 | 参数与下发路径都在：`0x2074` 使能、`0x205B` 阈值、`0x205C` 压缩比、`0x205D/0x205E` 起停时间、`0x205F` 膝宽、`0x2060` 侧链高通；上位机现在把开关也搬上了主界面，便于现场确认使能位 | 确认 DSP 是否读 `0x2074`；确认 `0x205C`（`value=param/1000`，0.05–0.999）在 DSP 里的量纲与作用点；若 ratio 实际应写成 1:N，需要改参数表 |

补充：问题单第 2 条与第 11 条的**上位机侧**都已做到「不做任何归一化、原样显示与下发」，真机上看到的 44/87 就是设备回读值。

## 5. 遗留 / 待确认

1. **问题单 11 的效果仍需固件闭环**：上位机只能保证「开关 + 阈值 + 压缩比」三样都写进设备；噪声门听起来有没有效果取决于 DSP，需要固件确认后再复测。
2. **问题单 2 的端点校准**未做（固件侧）；上位机不加补偿——加了就等于骗人，排查时反而看不出设备真实值。
3. 本轮没有改参数表：均衡器「复位」用的是界面 preset，`registers.ts` 的出厂默认仍是参数表 V0.3 的值。若产品希望**设备上电加载的预设**也是平直曲线，需要改参数表并重新出包。
4. 「快捷开关」卡现在只剩环境降噪一组；如果后续还想在主页放 RGB / 三分频的快捷开关，位置已经空出来了。
