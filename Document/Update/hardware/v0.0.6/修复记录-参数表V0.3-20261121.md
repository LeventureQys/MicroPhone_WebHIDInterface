配套事实：

- 预设区由 **114 项（止于 `0x2071`）变成 118 项（止于 `0x2075`）**。这正是前几轮真机联调里反复出现的「协议写 118 / 参数表 114」口径冲突的解法——**以参数表为准、扩到 118**，`PRESET_COUNT` 同步，`sync()` 的 `0x13` 连续读现在读 118 个字（响应 240 B，仍是 4 条 63 B 报告）。
- `效果器参数范围.xlsx` 里 3BandDrc 的 `fc1/fc2 = 1000/3000`、`preGain = 1.28` 与 V0.3 一致，说明这一版是**把参数表对齐到 DSP 实际默认值**；`attackTime/releaseTime` 两表仍有差异（参数表 1/5 ms，范围表 10/20 ms），按既有裁决**以参数表为准**。

## 2. 上位机侧改动

### 2.1 寄存器真值表（`src/renderer/src/device/registers.ts`）

- 真值源注释改指 `Document/Update/hardware/v0.0.6/M001参数表V0.3.xlsx`（V0.1 作废，仅备查）。
- `PRESET_COUNT` 114 → **118**；新增 `PRESET_END`、`NOISEGATE_ENABLE_ADDR`、`DRC3_ENABLE_ADDR`、`RGB_ONOFF_ADDR`、`RGB_MODE_ADDR` 常量。
- 按上表改 5 处默认值 / 范围，新增 4 行（`rgbOnOff` / `rgbMode` / `noisegateEnable` / `drc3Enable`，均 `access:'rw'`）。
- `REGISTERS` 190 → **194** 项。

### 2.2 参数模型（`domain/params.ts`）

- 42 → **46 项**，新增 `noisegate.Enable`（`0x2074`）、`drc3.Enable`（`0x2075`）、`rgb.OnOff`（`0x2072`）、`rgb.Mode`（`0x2073`）；
  新增 `ModuleId = 'rgb'`。
- 使能位排在本模块最前，界面上开关就落在参数滑杆上方。

### 2.3 旁通改真实使能位（`domain/state.ts` / `ui/views/**`）

2026-11-13 那版因「寄存器表没有 enable 位」，噪声门 / 三分频用**中性参数近似**旁通（阈值钉 -91 dB、三区 preGain=0 + ratio=1）。V0.3 补了使能位后：

- `AppStore.setBypass()` 只剩**均衡器**一项（协议确实没有全局 enable，写 7 段 `enable=0` 是真正的段旁通）；`BYPASS_PLAN` 与旁通快照表删除。
- 噪声门：高级参数「噪声门」卡顶部改出**噪声门开关**（`data-enable="noisegate"`，绑定 `noisegate.Enable`），关掉即直通，阈值不被动。
- 三分频动态：原「旁通」开关换成**三分频动态开关**（`data-enable="drc3"`，绑定 `drc3.Enable`），关掉后字段仍可编辑（值照常保存），不再禁用整片卡片。
- 一键场景（`domain/scenes.ts`）新增 `gateOn` / `drcOn`，四个固定场景与「自定义」都写 `1`——否则用户调了阈值却因为模块被关掉而不生效；`matchScene()` 也把这两个使能位纳入比对，手关开关后场景高亮自动取消。
- i18n 删掉 `module.bypass.noisegate` / `module.bypass.drc3`（中性旁通的说明），换成 `module.noisegate.bypassHint` / `module.drc3.bypassHint`。

### 2.4 灯效（新增 `ui/views/lighting-view.ts`）

高级参数抽屉新增第 5 个分区「灯效」（`advanced.section.lighting`）：`RGB 灯效` 开关 + `灯效模式`（0–7）。两项都直接读写寄存器，不做本地派生；模式含义由固件定义，界面只给提示。

### 2.5 虚拟下位机与自检（`tools/vdevice/**`）

- `device-stack.mjs`：`PRESET_END` 0x2071 → **0x2075**，`eqMode` 上限 5，`drc3Fc1/Fc2` 默认 1000/3000，三区 `preGain` 默认 128，新增 4 条 spec；默认寄存器表 190 → **194** 项。
- `selftest.mjs`：TIMING 镜像同步成 `writeThrottleMs = 300` + **尾沿触发**（与 `device/proto/session.ts` 一致）——这是已知坑 25（T07 在本机稳定失败）的根因，改完 `SUMMARY passed=20 failed=0`。

## 5. 真机误连与还原（如实记录）

第一版验证探针没有强制 mock 通道，本机插着 M001（固件 `0.0.5.0`）时 `auto-connect` 直接连上，探针的点击**写进了真机**（点击开关、切换「唱歌」场景、改灯效模式）。

处理：探针改为**先写 `localStorage` 切 mock 通道 + 关自动连接再 reload**，并加一条断言「整轮验证跑在 mock 通道（不碰真机）」；误写后另用 `scripts/probes/restore-device-v006-20261121.mjs` 走界面自己的「设置 → 复位全部参数」把设备还原成参数表 V0.3 默认值，回读：

```json
{"fc1":"1000","fc2":"3000","lowPreGain":"1.28","gateThreshold":"-91","compThreshold":"-2",
 "gateOn":true,"drcOn":true,"rgbOn":true,"rgbMode":"0","band1Gain":"0","band3Gain":"-3.5"}
```

注意：这轮之后设备上的 `0x2074` / `0x2075` 是 **1**（默认开），与 V0.0.5 出厂时的 0 不同；要恢复旧口径可按需要再关。取证在 `artifacts/verify-v006/restore.json` 与 `05/06-*.png`。

## 6. 遗留 / 待确认

1. **真机 V0.0.6 复测未做**：本机设备仍是 `0.0.5.0`，`0x2072`–`0x2075` 在旧固件里是「区间内但无功能」的地址，写进去会被 ACK 但不改变行为。`Document/Update/hardware/v0.0.6/` 下已有 `dfu_M001 MCU V0.0.6_2026-11-16_Rev0.bin`，可用界面「固件升级」刷入后再验：新默认值（1000/3000、1.28）、两个使能位真正旁通、RGB 灯效。

3. **RGB 模式 0–7 的灯效含义**由固件定义，界面只做 0–7 取值与提示。
4. `attackTime/releaseTime` 默认值在参数表（1/5 ms）与 `效果器参数范围.xlsx`（10/20 ms）仍不一致，按裁决用参数表；若固件实际按范围表实现，需要下一版对齐。
