## 2. 上位机改动明细

### 2.1 主界面（`ui/views/console-view.ts`、`styles/components.css`）

- **阈值行开关位置（问题 1）**：旧的 `.pfield--toggle .macro-toggle { margin-left:auto }` 把开关顶到卡片右边，读数宽度一变
  （`-80 dB` → `-4.1 dB`）开关就横向位移。现在标题行是"标题 → 开关 → 读数（`margin-left:auto` 靠右）"，
  开关紧跟文字、位置固定；探针实测改阈值前后 `toggle.left = 417.8 → 417.8`（0 px 漂移）。
- **灯效上主页（问题 5）**：`快捷开关` 卡从"一组环境降噪"变成两列：
  `环境降噪 [开关] / 档位 0-3` 与 `灯效 [开关] / 模式 0-7`。模式用 `segmented--modes`（8 个 chip 等分压缩，
  宽 380 px 时每个约 15 px、窄 340 px 时约 11 px），与高级参数「灯效」是同一组参数 id（`rgb.OnOff`/`rgb.Mode`），
  任一处改动另一处立刻回填。**没有**做成跨两列的宽行：那会让中栏多出 ~70 px，1266×783 下「快速调音」被挤到溢出。
- **场景条复位（问题 9）**：`SceneGrid` 末尾加 `复位` 按钮（`.scene-reset`，与场景卡等高、带 `reset` 图标），
  只复位**当前选中**的场景；没有选中场景（用户手动换过音色）时禁用。
- **场景应用**：选场景时按"出厂预设 + 该场景保存过的改动"一起写（参数 7 项 + 7 段增益），并把它设为 `AppState.activeScene`。
- **纵向预算**：为在 1266×783 里同时放下三行阈值 + 音色 + 三个输入开关 + 灯效，收紧了
  `.tune-grid` 间距（gap 12→10、分组 `padding-top` 16→12）、读数行距（4→2 px）、滑杆高度（24→22 px）；
  中栏第一张卡的 `.card-body` 加了 `overflow-y:auto` 兜底——窗口压到 700 高以下时卡片内部滚动，
  不会再出现"输入开关压在快捷开关上"（旧版在 1086×663 就有这个重叠，见 `artifacts/fulltest-20261121/ui-audit/ui-audit-1086x663-zh-console.png`）。

### 2.2 场景可编辑 + 自动保存（新增 `domain/scene-presets.ts`）

- 存储：`micstudio.scenes` 按场景 id 存 **sparse 差异**（`{ params: {...}, gains: [...] }`），
  只存用户真的改过的项；没动过的项继续跟 `SCENES` 出厂预设，版本升级时不会把旧值冻住。
  「自定义」音色的曲线另存 `micstudio.customEq`（7 个增益）。
- 读写：`sceneParams(id)` = 出厂值 + 覆盖值；`sceneGains(id, customEq)`；`recordSceneParams` / `recordSceneGains` /
  `clearSceneOverride` / `loadSceneOverrides` / `saveSceneOverrides`。所有入参都过 `findParam` + `quantize`，
  坏数据（未知 id、只读项、非数字、超范围）直接丢弃，绝不因为配置坏掉让界面打不开。
- 录制时机：`AppStore` 的 `PARAM_CHANGED_EVENT`（**只有用户改动会派发**，设备回读走 `applyEcho` 不派发），
  曲线拖拽与「均衡器复位」走 `persistCustomGains()`。应用场景时用 `applyingScene` 闸门挡住自动保存，
  否则"应用预设"会被当成"用户刚改的值"存下来，复位后永远回不到出厂值。
- 复位：清掉该场景的覆盖值 → 再按出厂预设应用一遍；「自定义」场景连用户拖的曲线一起清成平直线。

### 2.3 默认值（`domain/defaults.ts`、`domain/quick-controls.ts`、`domain/state.ts`）

- `PRODUCT_PARAM_DEFAULTS = { 'drc3.Enable': 0 }`（问题 6）：参数表 V0.3 的 G 列是 1，这里覆盖成 0，
  影响未连接时的显示、`MockTransport` 回读、设置页「复位全部参数」与场景预设。
- `PRODUCT_BAND_FREQS = [50, 20000, 63, 250, 1000, 4000, 12500]`（问题 2/3）：只换频点，类型 / 增益 / Q 继续取值表。

  上次存的自定义曲线套到 `bands`（`sync!=='ready'` 时 `setBands` 不发帧，连上设备后仍由回读接管）。

### 2.5 设置页「复位全部参数」按批写（验证中发现的固件侧问题）

- 现象：真机（V0.0.6）一次性写回几十项参数 + 7 段 EQ 之后，HID 不再消费 OUT 报告（`WriteFile timeout 2000 ms`），
  设备 product string 变空、Modbus 与 DFU 帧都不应答，只能物理拔插。**改前改后都能复现**（`git stash` 做过 A/B），
  与本轮改动无关，但用户的「复位全部参数」一定会碰到。
- 上位机侧处置：6 项一批、批间隔 320 ms（大于 `ParamSession` 的 300 ms 写合并窗口，保证每批单独成一帧），
  7 段 EQ 一段一次；`store.sync === 'error'` 时立即停手，不再继续压。按钮期间显示「正在复位…」并禁用。
  模拟通道不做等待（保持原来的瞬时复位）。
- 单测：`tests/unit/settings-reset.test.ts`（同步路径写全默认值 + 真机通道的分批节奏与按钮状态）。

### 2.6 自动连接多给两次"冷启动"重试

设备自己复位（固件重启）在 USB 上看起来就是"拔掉又插回"：`wasReady` 会被清零，一次同步失败就直接 `parked`，
用户得手动点「打开」。现在 `AutoConnector` 新增：

- `coldSyncRetries = 2`（间隔 2 s）：从没连上过时先给两次短的冷启动重试，仍失败才判定"停在升级模式"（~6 s 后停手）。
- `AutoConnectLink.onChange?()`：链路哪怕不是后台连上的（用户手动连接 / 会话恢复），也记住"这台设备曾经可用"。
- 单测：`auto-connect.test.ts` 新增「retries a cold device a couple of times before parking」「remembers a link that was connected outside the background connector」「gives a device that rebooted mid-session two cold sync retries」并把「parks immediately…」改成"两次冷重试后停手"。

### 2.7 文案

- `console.scene.desc`：选一个场景；改动会自动保存。
- `console.scene.reset` / `resetHint`：复位 / 把当前场景的参数恢复为默认值（改过的参数会自动保存，复位后清空）。
- `console.lighting` / `.mode` / `.hint`：灯效 / 模式 / 与高级参数的灯效是同一组寄存器。
- `settings.resetRunning`：正在复位…。
- 场景名 `console.scene.game`：游戏（英 Game / Low hiss, clear voice）。

## 5. 验证中发现的新问题（固件侧，已做上位机缓解）

**「设置 → 复位全部参数」之后设备不再应答**（M001，V0.0.6，本机 2026-11-23 复现 3 次）：
